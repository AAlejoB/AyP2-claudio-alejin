Post #1 — Los Cimientos: TAD, Packages y Genéricos

post #1 fundamental
📚
ManualteoríaPost #1

1 · El concepto de TAD (Tipo Abstracto de Datos)

El Porqué: un TAD separa el QUÉ hace una estructura del CÓMO lo hace. Te permite "ocultar" la representación interna y trabajar a nivel de operaciones. En la práctica esto significa que el cliente del package no puede meter mano a los campos internos: sólo puede llamar a los procedimientos públicos. A esto se le llama encapsulamiento.

Los tres niveles para el examen:

🧠 Nivel Lógico
Definición matemática del TAD: qué es, qué operaciones tiene, cuáles son sus pre y poscondiciones. Sin código. Es el contrato matemático.
⚙️ Nivel de Implementación
El código Ada concreto: archivos .ads (especificación) y .adb (cuerpo). Materializa el contrato del nivel lógico.
🎯 Nivel de Aplicación
Usar la estructura para resolver un problema (lo que hacés en los TPs cuando instanciás un package e implementás un programa).
Pregunta tipo "explicame": "¿Por qué Tipopila es private en la especificación?". Respuesta: porque la representación concreta (array + tope, lista enlazada, etc.) es decisión del implementador y no debe condicionar al cliente. El cliente sólo usa Meter / Sacar / Vacia / Llena — si el día de mañana cambiamos pila estática por dinámica, el código del cliente no cambia una línea.

2 · Packages y encapsulamiento

El Porqué: Ada usa archivos separados para forzar la disciplina entre interfaz e implementación. Es una herramienta del lenguaje que te empuja a programar bien — no es por capricho.

ArchivoQué contieneQuién lo ve
.ads (especificación) El "contrato": tipos públicos, firmas de subprogramas, excepciones, declaración private de la representación interna. Lo lee el cliente. Lo lee el compilador para chequear los tipos.
.adb (cuerpo) La implementación real de cada subprograma del .ads. Sólo el compilador. El cliente no necesita verlo (y no debería depender de él).

Sobre private en la especificación: hay una parte private en el .ads donde se declara cómo es realmente el tipo (por ejemplo, un record con punteros). Esa parte la lee el compilador para saber el tamaño, pero el cliente no puede usar esos campos. Es la frontera entre "lo que el cliente sabe" y "lo que el compilador necesita saber".

pila_dinamica.ads (esqueleto)generic
   type Tipoelem is private;
package Pila_Dinamica is
   --  Parte PÚBLICA: lo que el cliente puede usar
   type Tipopila is private;           --  tipo opaco
   Pila_Vacia : exception;
   procedure Crear (P : out Tipopila);
   procedure Meter (P : in out Tipopila; X : in  Tipoelem);
   procedure Sacar (P : in out Tipopila; X : out Tipoelem);
   function  Vacia (P : Tipopila) return Boolean;

private
   --  Parte PRIVADA: el cliente NO puede usar esto.
   --  El compilador sí lo necesita.
   type Nodo;
   type Tipopila is access Nodo;
   type Nodo is record
      Info : Tipoelem;
      Sig  : Tipopila;
   end record;
end Pila_Dinamica;

3 · Genéricos: el "molde maestro"

El Porqué: los genéricos permiten que una estructura (Vector, Pila, Cola, Lista) funcione con cualquier tipo de dato — Integer, Float, records, otros packages instanciados — sin reescribir ni una línea. El package actúa como una plantilla; cuando alguien lo necesita, "lo instancia" pasándole los tipos concretos.

Es exactamente el mismo concepto que los templates de C++ o los generics de Java, pero en Ada el contrato es explícito: vos declarás qué tipos y qué operaciones se le exigen al cliente.

🟡 Check de Dependencias · Crítico
Para que un programa que usa un vector genérico (estilo TP1 Ej 3) funcione, tienen que existir las tres cosas siguientes, en este orden, en tu proyecto:
  1. El archivo vec_generico.ads con la declaración generic y la especificación del package.
  2. El archivo vec_generico.adb con la implementación de cada subprograma declarado en el .ads.
  3. La instanciación en el programa cliente: 
    package Mi_Instancia is new Vec_Generico
  (Tipo_Elemento => Integer,
   Indice        => Mi_Rango,
   ...);  --  el resto de los formales que el .ads exige

Si falta cualquiera de los tres → no compila. Esto es lo primero que conviene chequear cuando el GNAT te tira un error críptico tipo "undefined" o "ambiguous": probablemente olvidaste instanciar o no agregaste el with en el archivo cliente.

Código riguroso · Molde básico del TP1

vec_generico.adsgeneric
   type Tipo_Elemento is private;       --  cualquier tipo con asignación / "="
   type Indice        is (<>);          --  cualquier tipo DISCRETO
package Vec_Generico is

   type Tipo_Vector is array (Indice) of Tipo_Elemento;

   procedure Leer     (V : out Tipo_Vector);
   procedure Imprimir (V : in  Tipo_Vector);

end Vec_Generico;

Cómo leer la firma de los formales genéricos:

  • type Tipo_Elemento is private; → "el cliente me pasa cualquier tipo que soporte asignación e igualdad". Por ejemplo Integer, Float, un record propio.
  • type Indice is (<>); → "el cliente me pasa un tipo discreto". Eso incluye Integer, Character, enumerados (type Dia is (Lu, Ma, Mi, ...)) y subtipos. La sintaxis (<>) es la forma de decir "discreto cualquiera".
🔴 Alertas de Cátedra · Bajan puntos
  • Paso de parámetros: usá in para sólo lectura, out para inicializar dentro del subprograma, y in out para modificar. Nunca declares out para un parámetro que querés leer dentro del cuerpo: su valor de entrada es indefinido.
  • Instanciación previa al uso: no podés declarar una variable de Tipo_Vector sin antes haber hecho la new del package genérico. La instancia crea el tipo concreto; sin ella, el tipo no existe.
  • Excepciones obligatorias: en TP1 (y en todos los TPs) tenés que capturar errores de dato o de rango. Pon exception al final del bloque y manejá al menos Constraint_Error y Data_Error. Si el profe ve un programa que crashea porque el usuario tipea una letra en vez de un número, te resta.
  • El cliente NO puede ver la representación interna: si el tipo es private, escribir V (1).campo_interno es ilegal. Sólo se accede via las operaciones públicas del package.
  • Nomenclatura de la cátedra: mantené Tipoelem, Tipovec, Tipopila, Meter, Sacar, Inscola, Supcola... si cambiás los nombres "porque me suenan mejor", el profe se ofusca aunque el código sea correcto.

🎤 Cómo lo explicarías en oral

"Un TAD es un contrato: define qué operaciones tiene una estructura y cómo se comportan, sin atarse a una implementación concreta. En Ada el TAD se materializa con un package dividido en .ads (especificación pública) y .adb (cuerpo privado). Si además quiero que el package sirva para distintos tipos de dato, lo declaro genérico: el cliente lo instancia pasando los tipos formales y el compilador me genera la versión específica. El encapsulamiento se garantiza con private: el cliente no puede ver ni tocar la representación interna, sólo invocar los subprogramas autorizados."

Post #2 — Excepciones: la malla de seguridad

post #2 obligatorio en TODOS los TPs
📚
ManualteoríaPost #2

1 · El Porqué

En lenguajes como C, los errores se manejan con códigos de retorno y muchos if repartidos por todos lados. Eso ensucia la lógica y obliga a verificar "después de cada llamada". Ada introduce las excepciones como una vía paralela: cuando algo va mal, el flujo salta al manejador más cercano, sin contaminar la lógica normal con condicionales.

Una excepción es un objeto con nombre, no un número. Tiene tipo, se lanza con raise, se captura con when ... =>, y si nadie la captura, propaga hacia arriba hasta encontrar un manejador o terminar el programa.

2 · Las dos categorías

CategoríaOrigenEjemplos
Predefinidas vienen con el lenguaje o el package estándar Constraint_Error, Storage_Error, Data_Error, End_Error
De usuario las declarás vos o tu package Pilavacia, Colavacia, Arbol_Vacio, Cero (caso TP1)

3 · Las predefinidas que te van a tocar

ExcepciónCuándo se lanzaOrigen
Constraint_Error valor fuera de rango (subtype), división por 0, índice fuera, dereferenciar null Standard
Storage_Error new falla por falta de heap; stack overflow Standard
Program_Error elaboración fuera de orden, función no devuelve valor Standard
Data_Error Get no puede parsear (entrada no es número) Ada.Text_IO
End_Error leer pasado el fin de archivo Ada.Text_IO
Name_Error archivo no existe en Open Ada.Text_IO
Mode_Error operación incompatible con el modo (escribir en In_File) Ada.Text_IO
🟡 Check de Dependencias
  • Constraint_Error, Storage_Error, Program_Error vienen del package Standard: no requieren with.
  • Data_Error, End_Error, Name_Error, Mode_Error requieren with Ada.Text_IO; (o Ada.Integer_Text_IO / Ada.Float_Text_IO según el caso).
  • Para vaciar el buffer tras Data_Error: Skip_Line de Ada.Text_IO.
  • Para declarar la tuya: una línea en la zona de declaraciones: Mi_Error : exception;

4 · Sintaxis — los 4 patrones canónicos

Patrón A · Captura básica

begin
   ...           --  código que puede fallar
exception
   when Constraint_Error =>
      Put_Line ("rango/null/div0");
   when Data_Error =>
      Put_Line ("entrada inválida");
   when others =>
      Put_Line ("cualquier otra cosa");
end;

Patrón B · Excepción de usuario

declare
   Pila_Vacia : exception;
   ...
begin
   if Top = 0 then raise Pila_Vacia; end if;
   ...
exception
   when Pila_Vacia => Put_Line ("no hay elementos");
end;

Patrón C · Reentrada en error (clásico TP1 Ej 6)

while not Valido loop
   begin
      Put ("Ingrese entero positivo: ");
      Get (N);
      Valido := True;
   exception
      when Data_Error =>
         Put_Line ("no es un entero, reintente");
         Skip_Line;                 --  ¡vaciar buffer!
      when Constraint_Error =>
         Put_Line ("debe ser positivo, reintente");
         Skip_Line;
   end;
end loop;

Patrón D · Propagar y atrapar más arriba

procedure Procesar (P : in out Tipopila) is
   X : Integer;
begin
   Sacar (P, X);                    --  puede lanzar Pilavacia
   ...
   --  Acá NO la capturo: propaga al llamador
end Procesar;

procedure Main is
begin
   Procesar (Mi_Pila);
exception
   when Pilavacia =>
      Put_Line ("la pila quedó vacía");
end Main;
🔴 Alertas de Cátedra
  • Skip_Line después de Data_Error es obligatorio. Sin él, la basura sigue en el buffer y el próximo Get dispara otra Data_Error. Es loop infinito de error.
  • El subtype filtra ANTES del raise manual. Si declarás Y : Rango (1..10) y querés if Y=0 then raise Cero, el Constraint_Error del Get ya saltó antes — tu raise Cero queda muerto (TP1 Ej 5 caso iv).
  • Una excepción atrapada NO se propaga. Si la atrapás dentro de un procedure y no le asignaste valor a los parámetros out antes, quedan indefinidos. El llamador no se entera del error y usa basura (TP1 Ej 5 caso v.d).
  • No abusar de when others =>: sirve para defensa final, pero esconde bugs si lo usás como atajo. En cada package, declará excepciones nominales (Pilavacia, Colavacia) y atrapalas por nombre.
  • En cada TP la cátedra exige considerar excepciones. El enunciado del TP4 lo dice literal: "En todos los packages se deben considerar las posibles excepciones". Si tu code no las maneja, perdés puntos seguros.

5 · Cómo lo explicarías en oral

"Una excepción en Ada es un objeto con nombre, no un número de error. Cuando ocurre algo anómalo se lanza con raise y el flujo salta al manejador when más cercano. Si no hay manejador, propaga al llamador. Las excepciones se dividen en predefinidas (Constraint_Error, Storage_Error, Data_Error...) y de usuario (declaradas con Mi_Error : exception;). Permiten separar la lógica normal del manejo de errores, evitando contaminar el código con condicionales."

Post #3 — Estructuras compuestas: patrones de conservación

post #3 TP2 · TP4
📚
ManualteoríaPost #3

1 · El Porqué

Cuando un TP pide "vector de pilas", "pila de listas", "cola de pila de listas de enteros"... lo que el profe te evalúa NO es si sabés meter dentro de meter dentro de meter. Lo que evalúa es: ¿podés acceder a la información sin destruir la estructura?

El problema fundamental: las estructuras LIFO/FIFO son opacas. Para "ver" el tope de una pila tenés que sacarlo. Para "ver" el frente de una cola tenés que desencolarlo. Eso pisa el estado original. Por eso existen los patrones de conservación: técnicas para ver/leer/procesar sin destruir.

2 · Los 4 patrones canónicos

Patrón 1 · Ver el tope de una pila sin destruirla

Sacar + Meter el mismo elemento inmediatamente. El estado de la pila queda indistinguible del original para el cliente.

--  Pre: not Vacia(P)        Post: P igual; result = elemento en el tope
function Tope (P : in out Tipopila) return Integer is
   X : Integer;
begin
   Sacar (P, X);
   Meter (P, X);
   return X;
end Tope;

Patrón 2 · Procesar todos los elementos de una pila conservándola

Pila auxiliar. La doble inversión preserva el orden: lo que sale primero entra último en la aux, y al volver sale último — vuelve a su lugar.

function Suma_Pila (P : in out Tipopila) return Integer is
   Aux : Tipopila;
   X   : Integer;
   S   : Integer := 0;
begin
   Crearpila (Aux);
   while not Vacia (P) loop
      Sacar (P, X); S := S + X; Meter (Aux, X);
   end loop;
   --  Restaurar: la doble inversión devuelve a P el orden original
   while not Vacia (Aux) loop
      Sacar (Aux, X); Meter (P, X);
   end loop;
   return S;
end Suma_Pila;

Patrón 3 · Acceder al frente de una cola sin destruirla

Cola auxiliar. Insertás primero el elemento "leído" en la aux, después transferís el resto en orden. La aux queda con la secuencia original. Reasignás.

--  Acceder al "frente" y conservar la cola intacta
procedure Procesar_Frente (Q : in out Tipocoladinamica) is
   Aux       : Tipocoladinamica;
   Frente, X : Tipo_Elem;
begin
   Supcola (Q, Frente);            --  saco el frente
   --  ... acá uso Frente para lo que necesite ...
   Crearcola (Aux);
   Inscola (Aux, Frente);          --  va PRIMERO en la aux
   while not Vacia (Q) loop
      Supcola (Q, X); Inscola (Aux, X);
   end loop;
   Q := Aux;                       --  la cola queda con el mismo orden
end Procesar_Frente;

Patrón 4 · Estructuras anidadas (cola de pila de listas, etc.)

Cuando el elemento es un access (puntero) o un record con campos puntero (como Tipocoladinamica, que es un record con Frente y Final): al copiar el elemento copiás los punteros, no el contenido. Eso significa dos cosas:

  • A favor: modificar el elemento "extraído" SÍ afecta al contenido (porque los punteros internos siguen vivos).
  • En contra: alias inesperado puede generar errores si no estás atento.
🟡 Check de Dependencias
Para anidar packages, las instanciaciones deben ir de adentro hacia afuera, en este orden:
  1. Instanciás el package del nivel más interno con el tipo concreto: 
    package LInt is new Listanoordenada (Integer);
  2. Instanciás el siguiente nivel usando el tipo del anterior: 
    package PList is new Piladinamica (LInt.Tipolista);
  3. Y así hasta el más externo: 
    package CPila is new Coladinamica (PList.Tipopiladinamica);

El tipo de cada nivel interno tiene que ser compatible con la cláusula is private del nivel externo. Los tipos access (Tipolista, Tipopiladinamica) lo cumplen porque soportan asignación e igualdad.

🔴 Alertas de Cátedra
  • "Se debe conservar la información" = usá auxiliar. Es la señal explícita en el enunciado. Si no aparece, igual conviene preguntarse: ¿espera el profe que la estructura sobreviva al procedure?
  • La firma Info de las listas de la cátedra devuelve COPIA. Si modificás esa copia, no afecta al nodo original. Para modificar el nodo hay que pasar el puntero o usar operaciones específicas del package.
  • El "info" de una cola dinámica es un record con punteros. Hacer Cola_Tope := Aux copia los dos punteros del record (Frente y Final); los nodos del heap no se duplican. Eso es lo que queremos cuando restauramos: usar la aux directamente como nueva cola.
  • Pila estática (Pilae) tiene discriminant. Para tener un array (1..5) of Tipopila todas las pilas deben compartir el mismo Max. Si querés Max distintos por posición, necesitás punteros a Tipopila.
  • Después de Supcola sobre cola vacía → Colavacia. Verificá not Vacia (Q) antes de cada Supcola en loops. Lo mismo para Sacar de pila vacía.

4 · Cómo lo explicarías en oral

"Las estructuras LIFO/FIFO son opacas: para acceder a su contenido tenés que sacar elementos, lo que las destruye. Para conservar la información existen patrones: Sacar + Meter para leer el tope de una pila, pila auxiliar para procesar todos los elementos con doble inversión, y cola auxiliar reconstruyendo en el mismo orden para preservar una cola. En estructuras anidadas lo importante es entender cuándo se copia el puntero (alias) y cuándo el contenido, porque modificar a través del alias sí afecta al original."

Post #4 — Memoria dinámica: access, new, free

post #4 TP3 · TP4
📚
ManualteoríaPost #4

1 · El Porqué

Hasta el TP2, los datos viven en el stack: nacen al entrar al bloque begin ... end, mueren al salir. Tamaño fijo, alcance limitado. Funciona, pero no alcanza.

A veces necesitamos:

  • Estructuras de tamaño desconocido en compilación (listas, árboles, grafos que crecen con el input).
  • Datos que sobrevivan al subprograma que los creó.
  • Compartir un objeto entre varias partes del programa sin copiarlo.

Solución: el heap. Memoria reservable dinámicamente con new, liberable con un Free instanciado de Ada.Unchecked_Deallocation.

2 · El kit de 5 piezas

--  (1) Declarar el tipo puntero
type T_Ptr is access Integer;

--  (2) Instanciar el Free específico para este tipo
procedure Free is new Ada.Unchecked_Deallocation
  (Integer, T_Ptr);

P : T_Ptr;
begin
   --  (3) Reservar memoria
   P := new Integer;

   --  (4) Asignar / leer el contenido
   P.all := 42;
   Put (P.all);

   --  Comparar con null
   if P /= null then ...

   --  (5) Liberar
   Free (P);              --  ahora P queda en null automáticamente
end;

3 · Forward declaration para tipos recursivos

Si querés un nodo que apunte a otro nodo del mismo tipo (lista, árbol), no podés usar el tipo antes de definirlo. Solución: declaración adelantada.

type Nodo;                    --  "ya viene la definición"
type Tipolista is access Nodo; --  ahora sí puedo usar Nodo
type Nodo is record            --  definición real
   Info : Tipo_Elem;
   Sig  : Tipolista;           --  recursión: nodo que apunta a otro nodo
end record;
🟡 Check de Dependencias
  • Para reservar memoria (new) no hace falta ningún with: es sintaxis del lenguaje base.
  • Para liberar memoria sí: 
    with Ada.Unchecked_Deallocation;
    y dentro del body, instanciar el procedure: 
    procedure Free is new Ada.Unchecked_Deallocation (Tipo, Tipo_Ptr);
  • Para tipos recursivos, la forward declaration type Nodo; es obligatoria antes del access.
  • Para comparar punteros, null está incorporado, no requiere with.
  • Para evitar Constraint_Error al dereferenciar: usá and then, no and: 
    while Ptr /= null and then Ptr.Info /= X loop ...
    Con and a secas, Ada evalúa ambos lados aún si el primero es falso → dereferenciás null → boom.

4 · Las 4 trampas que SIEMPRE caen en parcial

4.1 Fuga (memory leak)

P := new Integer;       --  bloque A reservado
P := new Integer;       --  bloque B reservado; A QUEDÓ HUÉRFANO (fuga)

Corrección: Free (P) antes de pisarlo.

4.2 Alias

P := new Integer; P.all := 5;
Q := P;                 --  Q y P apuntan al MISMO bloque
Q.all := 10;            --  ahora también P.all = 10

4.3 Dangling pointer

Q := P;                 --  alias
Free (P);               --  el bloque se liberó; P queda en null
                        --  pero Q SIGUE apuntando al bloque liberado: DANGLING
Q.all := 7;             --  comportamiento indefinido

4.4 Double free

Q := P;                 --  alias
Free (P);               --  libera
Free (Q);               --  intenta liberar lo mismo otra vez: UB
🔴 Alertas de Cátedra
  • Antes de pisar un puntero, free. "Pisar" significa cualquier reasignación: P := new ..., P := Q, etc.
  • Después de Free, Ada deja el puntero en null automáticamente (es garantía del Unchecked_Deallocation estándar). Por eso podés escribir if P /= null then Free (P); end if; y es seguro llamarlo dos veces — el segundo es un no-op.
  • Pero los ALIAS quedan dangling. Si Q := P; Free (P);, P queda null pero Q sigue apuntando al bloque ya liberado. Vos sos responsable de poner Q := null; manualmente.
  • "Unchecked" es por algo: el deallocator no verifica si hay alias vivos. Si hay, los crashes son tu responsabilidad. Por eso la convención es: un dueño por bloque, los alias se ponen en null cuando el dueño hace free.
  • Forward declaration es obligatoria para tipos recursivos. Olvidártela es error de compilación que el GNAT explica con sintaxis críptica. Si ves "undefined identifier Nodo" en una declaración recursiva, falta el type Nodo; arriba.

5 · Cómo lo explicarías en oral

"Ada permite memoria dinámica con tipos access. Una variable de tipo access guarda una dirección al heap; con new T reservo un bloque y con P.all dereferencio. Para liberar instanciar Ada.Unchecked_Deallocation con los tipos concretos, lo que me da un procedure Free. Hay cuatro errores típicos: fuga (pisar puntero sin liberar), alias (dos punteros al mismo bloque), dangling (usar puntero post-free) y double free. La regla es un dueño por bloque; los alias se ponen en null cuando el dueño libera. Para tipos recursivos hace falta forward declaration: type Nodo; antes del access type."

Post #5 — Listas enlazadas: el TAD favorito de la cátedra

post #5 TP4 · y todo lo que viene
📚
ManualteoríaPost #5

1 · El Porqué

Una lista enlazada es una secuencia de nodos donde cada nodo guarda un dato y un puntero al siguiente. El último apunta a null. Es la estructura dinámica más usada de toda la materia — aparece en TP2 (cuando se mete con punteros), y es el corazón del TP4.

Ventajas frente a un array:

  • Tamaño dinámico: crece y se achica según el input.
  • Inserción/supresión O(1) en el lugar correcto (si tenés el puntero al nodo anterior).
  • No necesita memoria contigua: los nodos pueden vivir dispersos en el heap.

Desventajas:

  • Acceso indexado O(n): no podés "saltar" al nodo 100 sin recorrer los 99 anteriores.
  • Overhead de memoria: cada nodo carga su puntero al siguiente.

2 · Las dos variantes que pide la cátedra

VarianteCuándoCaracterísticas
Listaordenada cuando el orden importa al buscar Insertar mantiene el orden — recibe Menor y Mayor como subprogramas formales
Listanoordenada cuando el orden lo decide el cliente tiene InsertarPpio (O(1)) y InsertarFin (O(n))

3 · Las operaciones críticas (las del TAD)

OperaciónCostoNotas
CrearlistaO(1)devuelve lista en null

EstaO(n)recorrido lineal con corte temprano

SigO(1)devuelve el puntero al siguiente

🟡 Check de Dependencias
  • Para usar Listaordenada debés proveer Menor y Mayor: 
    function Menor (X, Y : T) return Boolean is (X < Y);
function Mayor (X, Y : T) return Boolean is (X > Y);
package Mi_Lista is new Listaordenada (T, Menor, Mayor);
  • Para Listanoordenada: sólo el tipo de elemento. 
    package Mi_Lista is new Listanoordenada (T);
  • Internamente: ambas usan Ada.Unchecked_Deallocation para liberar nodos en Suprimir y Limpiar.
  • Recorrido fuera del package: sólo accedés con Info, Sig y Vacia (porque Tipolista es private). No podés escribir Mi_Lista.Cabeza.Info: la cabeza no está expuesta.

4 · Patrones canónicos de recorrido

Patrón A · Recorrido simple (lectura)

P : Tipolista := Mi_Lista;
while not Vacia (P) loop
   Procesar (Info (P));
   P := Sig (P);
end loop;

Patrón B · Recorrido con "anterior" para supresión

Ant : Tipolista := null;
Ptr : Tipolista := Mi_Lista;
while Ptr /= null and then Ptr.Info /= Buscado loop
   Ant := Ptr;
   Ptr := Ptr.Sig;
end loop;
if Ptr /= null then
   if Ant = null then               --  el buscado era la cabeza
      Mi_Lista := Ptr.Sig;
   else
      Ant.Sig := Ptr.Sig;
   end if;
   Free (Ptr);
end if;

Patrón C · Inserción ordenada (cuerpo de Listaordenada.Insertar)

Nuevo : Tipolista := new Tiponodo'(Elem, null);
Ant   : Tipolista := null;
Ptr   : Tipolista := Lista;
while Ptr /= null and then Menor (Ptr.Info, Elem) loop
   Ant := Ptr; Ptr := Ptr.Sig;
end loop;
Nuevo.Sig := Ptr;
if Ant = null then
   Lista := Nuevo;
else
   Ant.Sig := Nuevo;
end if;
🔴 Alertas de Cátedra
  • SIEMPRE usá and then al recorrer con condición sobre el nodo. Ptr /= null and then Ptr.Info = X es seguro; Ptr /= null and Ptr.Info = X evalúa Ptr.Info aún si Ptr es null → Constraint_Error.
  • Info de la lista de la cátedra LANZA Listavacia si la lista está vacía. Verificar antes con not Vacia (L).
  • Info devuelve una COPIA, no acceso al campo. Modificar lo que devuelve Info no modifica el nodo. Para modificar hay que exponer una operación o cambiar la firma del package.
  • Después de Free el nodo desenlazado, no podés tocar nada que apunte a él. Esa es la regla del Post #4 aplicada acá: si Q := Mi_Lista; Free (Mi_Lista);, Q queda dangling.
  • Para "vaciar" una lista, usá Limpiar del package, no Mi_Lista := null;. Si solo asignás null, dejás todos los nodos en el heap como fuga.
  • InsertarFin tiene costo O(n). Si vas a hacer muchas inserciones al final, considerá mantener un puntero al último, o usar listas dobles.

5 · Cómo lo explicarías en oral

"Una lista enlazada es una secuencia dinámica de nodos donde cada nodo guarda un dato y un puntero al siguiente. La última apunta a null. La cátedra ofrece dos variantes: ordenada, donde Insertar mantiene el orden usando funciones Menor y Mayor que se pasan como formales genéricos; y no ordenada, que ofrece InsertarPpio y InsertarFin. Internamente usan memoria dinámica con access y forward declaration del nodo. Los patrones de uso clásicos son: recorrido lineal con Info/Sig, recorrido con dos punteros (ant, ptr) para supresión, e inserción ordenada con búsqueda de la posición correcta. Siempre se recorren con and then para evitar dereferenciar null."

Ejercicio 1 — Package genérico básico para arreglos unidimensionales

genéricos arreglos 1D
CÁ
CátedraProfeEnunciado original

Programar el package genérico básico para arreglos unidimensionales. Debe contemplar lectura e impresión.

YO
AlejoYoResolución

📝 Idea general

Un package genérico es una plantilla: vos no conocés ni el tipo de los elementos ni el tipo del índice cuando escribís el código. Cuando alguien lo instancia, le pasa esos tipos como parámetros y recién ahí el compilador genera la versión concreta.

🔑 Conceptos clave de Ada

  • type Tipo_Indice is (<>); → "el que me instancie va a darme un tipo discreto" (entero, carácter o enumerado). Esto me deja iterar con for I in V'Range loop.
  • type Tipo_Componente is private; → "cualquier tipo, pero adentro solo lo trato como caja negra (asignación e igualdad)". Si necesito leer/imprimir, debo recibir cómo hacerlo como subprograma formal.
  • with procedure Leer_Componente (X : out Tipo_Componente); → parámetro formal de subprograma. El cliente del package es responsable de pasar la versión correcta.
  • type Vector is array (Tipo_Indice range <>) of Tipo_Componente; → tipo no restringido: el rango se decide al declarar la variable concreta (un unconstrained array).

Especificación

Ejercicio 2 — Package genérico completo para arreglos unidimensionales

genéricos arreglos 1D norma · orden · búsqueda
CÁ
CátedraProfeEnunciado

Sumar al package del ejercicio 1: comparación entre arreglos (por norma euclídea), ordenamiento, y búsqueda que retorne posición + booleano.

Norma de un vector = √(v₁² + v₂² + … + vₙ²). Si ‖A‖ > ‖B‖ entonces A > B.
YO
AlejoYoResolución

📝 Idea general

Para hacer norma necesito sumar y multiplicar componentes. Para ordenar y comparar necesito <. Para buscar necesito =. Pero private no garantiza ninguna de esas operaciones, así que las pido como parámetros formales.

Para sacar la raíz cuadrada necesito convertir a Float: el cliente me pasa la función A_Float. Así el package no asume si los componentes son enteros, fixed o float.

💻 Código

Especificación

arreglos_1d_completo.adsgeneric
   type Tipo_Indice     is (<>);
   type Tipo_Componente is private;

   Cero : Tipo_Componente;     -- elemento neutro de la suma

   with function "+" (A, B : Tipo_Componente) return Tipo_Componente is <>;
   with function "*" (A, B : Tipo_Componente) return Tipo_Componente is <>;
   with function "<" (A, B : Tipo_Componente) return Boolean         is <>;
   with function "=" (A, B : Tipo_Componente) return Boolean         is <>;

   with function A_Float (X : Tipo_Componente) return Float;

   with procedure Leer_Componente     (X : out Tipo_Componente);
   with procedure Imprimir_Componente (X : in  Tipo_Componente);

package Arreglos_1D_Completo is

   type Vector is array (Tipo_Indice range <>) of Tipo_Componente;

   procedure Leer    (V : out Vector);
   procedure Mostrar (V : in  Vector);

   function  Norma   (V : Vector) return Float;

   --  A es "mayor" que B si su norma es mayor.
   function  Mayor (A, B : Vector) return Boolean;

   procedure Ordenar (V : in out Vector);

   --  Busca X en V. Si está, devuelve la posición y True.
   --  Si no está, Pos queda en V'First y Encontrado en False.
   procedure Buscar (V          : in  Vector;
                     X          : in  Tipo_Componente;
                     Pos        : out Tipo_Indice;
                     Encontrado : out Boolean);

end Arreglos_1D_Completo;

Cuerpo

arreglos_1d_completo.adbwith Ada.Text_IO;             use Ada.Text_IO;
with Ada.Numerics.Elementary_Functions;
use  Ada.Numerics.Elementary_Functions;

package body Arreglos_1D_Completo is

   procedure Leer (V : out Vector) is
   begin
      for I in V'Range loop
         Put ("V(" & Tipo_Indice'Image (I) & ") = ");
         Leer_Componente (V (I));
      end loop;
   end Leer;

   procedure Mostrar (V : in Vector) is
   begin
      for I in V'Range loop
         Put ("V(" & Tipo_Indice'Image (I) & ") = ");
         Imprimir_Componente (V (I));
         New_Line;
      end loop;
   end Mostrar;

   function Norma (V : Vector) return Float is
      Suma : Tipo_Componente := Cero;
   begin
      for I in V'Range loop
         Suma := Suma + V (I) * V (I);
      end loop;
      return Sqrt (A_Float (Suma));
   end Norma;

   function Mayor (A, B : Vector) return Boolean is
   begin
      return Norma (A) > Norma (B);
   end Mayor;

   --  Ordenamiento por selección: simple y suficiente para el TP.
   procedure Ordenar (V : in out Vector) is
      Min_Idx : Tipo_Indice;
      Tmp     : Tipo_Componente;
   begin
      for I in V'First .. Tipo_Indice'Pred (V'Last) loop
         Min_Idx := I;
         for J in Tipo_Indice'Succ (I) .. V'Last loop
            if V (J) < V (Min_Idx) then
               Min_Idx := J;
            end if;
         end loop;
         if Min_Idx /= I then
            Tmp           := V (I);
            V (I)         := V (Min_Idx);
            V (Min_Idx)   := Tmp;
         end if;
      end loop;
   end Ordenar;

   procedure Buscar (V          : in  Vector;
                     X          : in  Tipo_Componente;
                     Pos        : out Tipo_Indice;
                     Encontrado : out Boolean)
   is
   begin
      Encontrado := False;
      Pos        := V'First;
      for I in V'Range loop
         if V (I) = X then
            Pos        := I;
            Encontrado := True;
            return;
         end if;
      end loop;
   end Buscar;

end Arreglos_1D_Completo;

Ejercicio 4 — Package genérico completo para arreglos bidimensionales

genéricos arreglos 2D orden · trasposición
CÁ
CátedraProfeEnunciado

Agregar al pkg 2D: comparación por porcentaje (índice = % de elementos de A que son mayores a sus correspondientes en B), ordenamiento por columna pivote (mover filas completas), búsqueda y trasposición.

YO
AlejoYoResolución

📝 Decisiones de diseño

  • Comparación: recorro la matriz, cuento cuántas veces A(F,C) > B(F,C), divido por el total. Devuelvo un Float en [0..1]. Las matrices deben tener los mismos rangos; si no, va Constraint_Error.
  • Ordenamiento: recibe la columna pivote como parámetro y mueve filas enteras. Uso ordenamiento por selección sobre los índices de fila comparando M(F, Pivote).
  • Trasposición: el problema clásico es que Matriz(F, C) y su traspuesta Matriz(C, F) tienen tipos distintos (filas y columnas son tipos diferentes). Lo correcto en Ada es declarar un segundo tipo Matriz_T con los índices invertidos.

         end loop;
      end loop;
   end Leer;

   procedure Mostrar (M : in Matriz) is
   begin
      for F in M'Range (1) loop
         for C in M'Range (2) loop
            Imprimir_Componente (M (F, C)); Put (" ");
         end loop;
         New_Line;
      end loop;
   end Mostrar;

   function Indice_Mayor (A, B : Matriz) return Float is
      Mayores : Natural := 0;
      Total   : Natural := 0;
   begin
      for F in A'Range (1) loop
         for C in A'Range (2) loop
            Total := Total + 1;
            if A (F, C) > B (F, C) then
               Mayores := Mayores + 1;
            end if;
         end loop;
      end loop;
      if Total = 0 then
         return 0.0;
      end if;
      return Float (Mayores) / Float (Total);
   end Indice_Mayor;

   procedure Ordenar (M : in out Matriz; Pivote : in Tipo_Col) is
      Min_F : Tipo_Fila;
      Tmp   : Tipo_Componente;
   begin
      for F in M'First (1) .. Tipo_Fila'Pred (M'Last (1)) loop
         Min_F := F;
         for K in Tipo_Fila'Succ (F) .. M'Last (1) loop
            if M (K, Pivote) < M (Min_F, Pivote) then
               Min_F := K;
            end if;
         end loop;
         if Min_F /= F then
            --  Intercambia la fila completa
            for C in M'Range (2) loop
               Tmp           := M (F, C);
               M (F, C)      := M (Min_F, C);
               M (Min_F, C)  := Tmp;
            end loop;
         end if;
      end loop;
   end Ordenar;

   procedure Buscar (M          : in  Matriz;
                     X          : in  Tipo_Componente;
                     Fila       : out Tipo_Fila;
                     Col        : out Tipo_Col;
                     Encontrado : out Boolean)
   is
   begin
      Encontrado := False;
      Fila := M'First (1);
      Col  := M'First (2);
      for F in M'Range (1) loop
         for C in M'Range (2) loop
            if M (F, C) = X then
               Fila       := F;
               Col        := C;
               Encontrado := True;
               return;
            end if;
         end loop;
      end loop;
   end Buscar;

   function Traspuesta (M : Matriz) return Matriz_T is
      R : Matriz_T (M'Range (2), M'Range (1));
   begin
      for F in M'Range (1) loop
         for C in M'Range (2) loop
            R (C, F) := M (F, C);
         end loop;
      end loop;
      return R;
   end Traspuesta;

end Arreglos_2D_Completo;
Detalle Ada: en el ordenamiento, Tipo_Fila'Pred y Tipo_Fila'Succ me permiten avanzar/retroceder en cualquier tipo discreto. Si Tipo_Fila fuese un enumerado como (Norte, Sur, Este, Oeste), esto sigue funcionando.
Trasposición y unconstrained arrays: Matriz_T debe ser un tipo distinto porque la traspuesta tiene el índice de filas tomado del tipo de columnas y viceversa. Si los índices fuesen iguales (matriz cuadrada con un solo tipo), podríamos retornar un Matriz.

   --  Funciones booleanas de "dimensiones adecuadas"

   function Dim_Igual_VV (V, W : Tipovec) return Boolean is
   begin
      return V'First = W'First and V'Last = W'Last;
   end Dim_Igual_VV;

   --  Para producto V (1xN) · M (NxM): V'Length debe igualar #filas de M
   function Dim_VM (V : Tipovec; M : Tipomat) return Boolean is
   begin
      return V'Length = M'Length (1);
   end Dim_VM;

   --  Pre : Dim_Igual_VV (V, W)
   --  Post: para todo I in Indice, R(I) = V(I) + W(I)

   function Suma_Vec (V, W : Tipovec) return Tipovec is

   begin
      if not Dim_Igual_VV (V, W) then raise Constraint_Error; end if;
      for I in Indice loop R (I) := V (I) + W (I); end loop;
      return R;
   end Suma_Vec;

   function Prod_Esc (V, W : Tipovec) return Integer is
      S : Integer := 0;
   begin
      if not Dim_Igual_VV (V, W) then raise Constraint_Error; end if;
      for I in Indice loop S := S + V (I) * W (I); end loop;
      return S;
   end Prod_Esc;

   function Prod_VM (V : Tipovec; M : Tipomat) return Tipovec is
      R : Tipovec;
   begin
      if not Dim_VM (V, M) then raise Constraint_Error; end if;
      for J in Columna loop
         R (J) := 0;
         for I in Fila loop R (J) := R (J) + V (I) * M (I, J); end loop;

algoritmo dígito verificador
CÁ
CátedraProfeEnunciado

📝 Idea

El dígito verificador del CUIL/CUIT se calcula con los pesos (5,4,3,2,7,6,5,4,3,2) aplicados a los primeros 10 dígitos. dv = 11 − (Σ dᵢ·wᵢ) mod 11. Casos de borde: si da 11 → 0, si da 10 → 9.

💻 Código

tp2_ej2.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;

procedure Tp2_Ej2 is

   type Sexo is (Masculino, Femenino);

   subtype DNI_Range  is Natural range 1_000_000   .. 99_999_999;     -- 7 u 8 dígitos
   subtype CUIL_Range is Natural range 20_000_000_000 .. 27_999_999_999;

   --  Pre : DNI in DNI_Range
   --  Post: result es el dígito verificador del CUIL = Pref·10⁸ + DNI
   function Verificador (Pref : Natural; DNI : Natural) return Natural is
      Pesos   : constant array (1 .. 10) of Natural := (5,4,3,2,7,6,5,4,3,2);
      Digitos : array (1 .. 10) of Natural;
      Valor   : Natural := Pref * 100_000_000 + DNI;
      Suma    : Natural := 0;
      M       : Natural;
   begin
      for I in reverse 1 .. 10 loop
         Digitos (I) := Valor mod 10;
         Valor       := Valor / 10;
      end loop;
      for I in 1 .. 10 loop
         Suma := Suma + Digitos (I) * Pesos (I);
      end loop;
      M := 11 - (Suma mod 11);
      if    M = 11 then return 0;
      elsif M = 10 then return 9;
      else            return M;
      end if;
   end Verificador;

   --  Pre : DNI ∈ DNI_Range
   --  Post: imprime el CUIL en pantalla con formato Pref-DNI-dv
   procedure Alta_CUIL (S : in Sexo; DNI : in Natural) is
      Pref : Natural;
      D    : Natural;
   begin
      if S = Masculino then Pref := 20; else Pref := 27; end if;
      D := Verificador (Pref, DNI);
      Put ("CUIL: "); Put (Pref, 0); Put ("-"); Put (DNI, 0); Put ("-"); Put (D, 0);
      New_Line;
   end Alta_CUIL;

   --  Pre : ninguna
   --  Post: True ⇔ CUIL tiene 11 dígitos, prefijo válido y dv correcto
   function CUIL_Valido (CUIL : Natural) return Boolean is
      Pref : Natural := CUIL / 1_000_000_000;
      DNI  : Natural := (CUIL mod 1_000_000_000) / 10;
      Dig  : Natural := CUIL mod 10;
   begin
      if Pref /= 20 and Pref /= 27 then return False; end if;
      return Dig = Verificador (Pref, DNI);
   end CUIL_Valido;

   C : Natural;
begin
   --  a) Alta de prueba
   Alta_CUIL (Masculino, 31_000_000);
   Alta_CUIL (Femenino,  35_500_000);

   --  b) Validación con reentrada en error
   loop
      begin
         Put ("Ingresá un CUIL completo (sin guiones) para validar: ");
         Get (C);
         if CUIL_Valido (C) then
            Put_Line ("→ CUIL válido ✔");
         else
            Put_Line ("→ CUIL inválido ✘");
         end if;
         exit;
      exception
         when Data_Error =>
            Put_Line ("Eso no era un número. Reintentá.");
            Skip_Line;
      end;
   end loop;
end Tp2_Ej2;

   procedure Getint (X : out Integer) is begin null; end Getint;     --  no se usa

   package Vint is new Vec_Simple (Integer, Indice, Putint, Getint);
   use Vint;

   package PFlt is new Pilae (Float);
   use PFlt;

   package Aleat is new Ada.Numerics.Discrete_Random (Pequeño);
   G : Aleat.Generator;

   --  Pre : la pila P tiene capacidad ≥ 3.
   --  Post: P queda con (de cabeza a base) Suma, Productoria_Pares, Promedio.
   procedure GenerarPila (V : in Tipovec; P : in out PFlt.Tipopila) is
      Suma_T : Integer := 0;
      Prod_P : Float   := 1.0;
      Hubo_P : Boolean := False;
      Prom   : Float;
   begin
      for I in Indice loop
         Suma_T := Suma_T + V (I);
         if V (I) mod 2 = 0 then
            Prod_P := Prod_P * Float (V (I));
            Hubo_P := True;
         end if;
      end loop;
      if not Hubo_P then Prod_P := 0.0; end if;
      Prom := Float (Suma_T) / Float (Indice'Last - Indice'First + 1);

      Limpiar (P);
      Meter (P, Prom);            --  base
      Meter (P, Prod_P);          --  medio
      Meter (P, Prom + Prod_P);   --  cabeza
   end GenerarPila;

   V : Tipovec;
   P : PFlt.Tipopila (10);
   X : Float;
begin
   Aleat.Reset (G);
   for I in Indice loop V (I) := Aleat.Random (G); end loop;
   Put ("Vector: "); Imprimir (V); New_Line;

   GenerarPila (V, P);

   Put_Line ("Pila (cabeza → base):");
   while not Vacia (P) loop
      Sacar (P, X);
      Put (X, Fore => 5, Aft => 2, Exp => 0); New_Line;
   end loop;
end Tp2_Ej3;
Orden de la pila: el primer Meter queda en la base y el último en la cabeza. Por eso el orden es Promedio → Productoria → Suma. Al sacar, salen al revés.

strings conjuntos

📝 Idea

Para "diferentes" uso un array (Character) of Boolean como conjunto: marco cada carácter visto y si ya estaba lo ignoro. Para vocales, recorrido lineal con case o un or sobre la versión minúscula.

💻 Código

tp2_ej4.adbwith Ada.Text_IO; use Ada.Text_IO;

procedure Tp2_Ej4 is

   --  Pre : ninguna.
   --  Post: Dig contiene la cantidad de dígitos distintos en S
   --        Letras contiene la cantidad de letras (a-z, A-Z) distintas
   procedure Contar_Distintos (S      : in  String;
                               Dig    : out Natural;
                               Letras : out Natural)
   is
      Vistos : array (Character) of Boolean := (others => False);
   begin
      Dig := 0; Letras := 0;
      for I in S'Range loop
         if not Vistos (S (I)) then
            Vistos (S (I)) := True;
            case S (I) is
               when '0' .. '9'              => Dig    := Dig    + 1;
               when 'a' .. 'z' | 'A' .. 'Z' => Letras := Letras + 1;
               when others                  => null;
            end case;
         end if;
      end loop;
   end Contar_Distintos;

   --  Pre : ninguna.
   --  Post: result = #vocales en S (sensible a mayúsculas, contempla acentos básicos)
   function Contar_Vocales (S : String) return Natural is
      C : Natural := 0;
   begin
      for I in S'Range loop
         case S (I) is
            when 'a'|'e'|'i'|'o'|'u'|
                 'A'|'E'|'I'|'O'|'U' => C := C + 1;
            when others              => null;
         end case;
      end loop;
      return C;
   end Contar_Vocales;

   Linea  : String (1 .. 200);
   Last   : Natural;
   D, L   : Natural;

   Put_Line ("Letras distintas:"   & Natural'Image (L));

   Put_Line ("Ingresá un texto (b):"); Get_Line (Linea, Last);

end Tp2_Ej4;

Ejercicio 5 — Vagones · permutaciones por pila

pila teórico
CÁ
CátedraProfeEnunciado

Un taller con vía de entrada, taller (pila LIFO) y vía de salida. ¿Se puede transformar 123456 en 325641? ¿Y en 154623?

YO
AlejoYoResolución

📝 Modelo

El taller es una pila. Cada movimiento es push (de la entrada al taller) o pop (del taller a la salida). Pregunta: ¿qué permutaciones de la salida son alcanzables? Respuesta clásica: las que evitan el patrón 312 (es decir, no puede haber tres números a, b, c que aparezcan en la salida con orden relativo c < a < b y posiciones b … a … c). Se prueba simulando.

🔁 Caso 1 — 325641: posible

#AcciónEntradaTaller (cima→base)Salida
0inicio1 2 3 4 5 6——
1push 12 3 4 5 61—
2push 23 4 5 62 1—
3push 34 5 63 2 1—
4pop 34 5 62 13
5pop 24 5 613 2
6push 45 64 13 2
7push 565 4 13 2
8pop 564 13 2 5
9push 6—6 4 13 2 5
10pop 6—4 13 2 5 6
11pop 4—13 2 5 6 4
12pop 1——3 2 5 6 4 1 ✓

🔁 Caso 2 — 154623: imposible

Sale 1 primero ⇒ push 1, pop 1. Sale 5 después ⇒ tengo que push 2, 3, 4, 5 (taller queda 5 4 3 2), pop 5. Sale 4 ⇒ pop 4. Sale 6 ⇒ push 6, pop 6. Taller queda 3 2. Pero ahora el siguiente esperado es 2, y la cima es 3: para llegar a 2 tengo que sacar 3 antes — pero 3 sale después de 2 según la salida pedida (… 2 3).

El conflicto es justo el patrón 3-1-2: 3 fue empujado antes de 2, así que en el taller queda 2 abajo y 3 arriba; pero la salida exige sacar 2 antes que 3. Con LIFO eso es físicamente imposible.

Regla rápida que te ahorra tiempo en el parcial: una permutación de 1..n es alcanzable por una pila si y solo si no contiene el patrón 3‑1‑2 (Knuth, 1968). Buscás tres índices i < j < k en la salida con valores π(k) < π(i) < π(j). Si los encontrás, no se puede.

Ejercicio 6 — Cola: extraer impares conservando los pares (sin auxiliares)

cola dinámica centinela
CÁ
CátedraProfeEnunciado

Dada una cola de enteros positivos distintos, extraer los impares conservando la cola. No usar estructuras auxiliares — solo la cola dada.

YO
AlejoYoResolución

📝 Idea

El package Coladinamica no expone el tamaño. Para saber cuándo "ya di una vuelta" sin estructura extra, inserto un centinela: un valor que sabemos que no aparece en la cola. Como el enunciado dice "enteros positivos", el 0 es un centinela perfecto. Recorro: si es par lo reinscribo, si es impar lo proceso, hasta toparme con el centinela.

💻 Código

tp2_ej6.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Coladinamica;

procedure Tp2_Ej6 is

   package CInt is new Coladinamica (Integer);
   use CInt;

   --  Pre : todos los elementos de C son enteros > 0.
   --  Post: C contiene sólo los pares originales en su orden relativo.
   --        Los impares se imprimen en pantalla a medida que se extraen.
   procedure Extraer_Impares (C : in out Tipocoladinamica) is
      Marca : constant Integer := 0;   --  centinela: 0 ∉ enteros positivos
      X     : Integer;
   begin
      if Vacia (C) then return; end if;
      Inscola (C, Marca);
      loop
         Supcola (C, X);
         exit when X = Marca;
         if X mod 2 = 0 then
            Inscola (C, X);            --  conserva el par
         else
            Put ("Extraído impar:" & Integer'Image (X)); New_Line;
         end if;
      end loop;
   end Extraer_Impares;

   ---------- Demo ----------
   C : Tipocoladinamica;
begin
   Crearcola (C);
   for I in 1 .. 8 loop Inscola (C, I); end loop;   --  1..8
   Extraer_Impares (C);

   Put ("Cola final (debería ser 2 4 6 8):");
   while not Vacia (C) loop
      declare X : Integer; begin
         Supcola (C, X); Put (Integer'Image (X));
      end;
   end loop;
   New_Line;
end Tp2_Ej6;
Por qué funciona el centinela: después de insertar el centinela, la cola tiene exactamente N+1 elementos. Cada Supcola lo acerca al frente, y los Inscola de los pares no lo alcanzan porque van detrás de él. Cuando lo desencolamos, sabemos que ya recorrimos todos los originales exactamente una vez.
Si los enteros pudieran ser cero o negativos, el truco no funciona y hay que recurrir a Limpiar+rebuild o a usar dos pasadas con el "tamaño implícito".

Ejercicio 7 — Vector de pilas

vec[5] of pila tope sin destruir
CÁ
CátedraProfeEnunciado

Un vector de 5 pilas. a) Imprimir la cabeza de las pilas que están en posiciones impares. b) Imprimir la suma de las pilas en posiciones pares.

YO
AlejoYoResolución

📝 Idea

Para leer el tope sin perderlo: Sacar + Meter el mismo elemento. Para sumar conservando la pila: paso todo a una pila auxiliar acumulando, y después restauro (la doble inversión deja la pila original intacta).

💻 Código

tp2_ej7.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Pilae;

procedure Tp2_Ej7 is

   subtype Indice    is Positive range 1 .. 5;
   Capacidad : constant Positive := 10;

   package PInt is new Pilae (Integer);
   use PInt;

   type Vec_De_Pilas is array (Indice) of Tipopila (Capacidad);

   --  Pre : not Vacia (P)        Post: P queda igual; result = elemento cabeza
   function Tope (P : in out Tipopila) return Integer is
      X : Integer;
   begin
      Sacar (P, X);
      Meter (P, X);
      return X;
   end Tope;

   --  Pre : ninguna             Post: P vuelve a su estado original; result = Σ elementos
   function Suma_Pila (P : in out Tipopila) return Integer is
      Aux : Tipopila (Capacidad);
      X   : Integer;
      S   : Integer := 0;
   begin
      Limpiar (Aux);
      while not Vacia (P) loop
         Sacar (P, X); S := S + X; Meter (Aux, X);
      end loop;
      while not Vacia (Aux) loop
         Sacar (Aux, X); Meter (P, X);
      end loop;
      return S;
   end Suma_Pila;

   V : Vec_De_Pilas;
begin
   --  Cargo cada pila con valores reproducibles
   for I in Indice loop
      Limpiar (V (I));
      for K in 1 .. 4 loop Meter (V (I), I * 10 + K); end loop;
   end loop;

   Put_Line ("a) Topes de pilas en posiciones impares:");
   for I in Indice loop
      if I mod 2 = 1 then
         Put_Line ("V(" & Indice'Image (I) & ").tope =" &
                   Integer'Image (Tope (V (I))));
      end if;
   end loop;

   Put_Line ("b) Suma de pilas en posiciones pares:");
   for I in Indice loop
      if I mod 2 = 0 then
         Put_Line ("V(" & Indice'Image (I) & ").Σ =" &
                   Integer'Image (Suma_Pila (V (I))));
      end if;
   end loop;
end Tp2_Ej7;
Detalle de Ada: Tipopila tiene un discriminant (Max:Positive). Para tener un array de pilas todas con la misma capacidad escribís array (Indice) of Tipopila (Capacidad). Si quisieras mezclar capacidades distintas, necesitarías punteros.

📝 Idea

with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Pilae;

procedure Tp2_Ej8 is

   subtype Indice is Positive range 1 .. 5;
   type Tipovec is array (Indice) of Integer;

   package PVec is new Pilae (Tipovec);
   use PVec;

   Capacidad : constant Positive := 10;

   --  Pre : ninguna     Post: result = sum (V(I))
   function Sumar (V : Tipovec) return Integer is
      S : Integer := 0;
   begin
      for I in Indice loop S := S + V (I); end loop;
      return S;
   end Sumar;

   --  Pre : not Vacia (P)
   --  Post: P igual; result = sumatoria del vector que está en la cabeza
   function Suma_Cabeza (P : in out Tipopila) return Integer is
      V : Tipovec;
   begin
      Sacar (P, V); Meter (P, V);
      return Sumar (V);
   end Suma_Cabeza;

   --  Pre : not Vacia (P)
   --  Post: P igual; result = posición desde la cabeza (1..N) del vector con suma máxima.

      Mejor_S    : Integer := Integer'First;
      Es_Primero : Boolean := True;

      while not Vacia (P) loop
         Sacar (P, V);
         Pos := Pos + 1;

               Mejor_S := S; Mejor_Pos := Pos; Es_Primero := False;

         end;

      end loop;
      while not Vacia (Aux) loop
         Sacar (Aux, V); Meter (P, V);
      end loop;
      return Mejor_Pos;
   end Pos_Mayor_Suma;

   ---------- Demo ----------
   P : Tipopila (Capacidad);

   Meter (P, (9, 8, 7, 6, 5));         --  Σ = 35  (cabeza)

end Tp2_Ej8;

tp2_ej9.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Piladinamica;
with Coladinamica;

procedure Tp2_Ej9 is

   subtype Indice is Positive range 1 .. 5;
   type Tipovec is array (Indice) of Integer;

   package PVec  is new Piladinamica (Tipovec);
   package CPila is new Coladinamica (PVec.Tipopiladinamica);
   use PVec, CPila;

   --  Pre : la cola no está vacía y la pila del frente no está vacía.
   --  Post: la cola y la pila vuelven a su estado original; result es el índice
   --        del elemento mayor del vector cabeza de la pila frente.
   function Pos_Max (Q : in out Tipocoladinamica) return Indice is
      P   : PVec.Tipopiladinamica;
      V   : Tipovec;
      Pos : Indice := Indice'First;
   begin
      --  Saco la pila del frente
      Supcola (Q, P);
      --  Saco el vector de la cabeza
      Sacar (P, V);

      for I in Indice loop
         if V (I) > V (Pos) then Pos := I; end if;
      end loop;

      --  Restauro
      Meter (P, V);
      Inscola (Q, P);   --  ojo: la pila vuelve al final de la cola

   Meter (P1, (10, 7, 3, 99, 1));    --  cabeza ← acá el mayor está en pos 4
   Inscola (Q, P1);

Ejercicio 10 — Reconocedor del lenguaje W·C·Wᴿ

pila estática palíndromos
CÁ
CátedraProfeEnunciado

Reconocer hileras de la forma W · C · Wᴿ donde W ∈ {a,b}* y C = 'c' (puede o no estar). Ej.: c, aca, bcb, bacab, abbcbba.

YO
AlejoYoResolución

📝 Idea

El lenguaje son los palíndromos en {a,b,c} donde la c aparece como mucho una vez y, si aparece, está en el centro exacto. Algoritmo:

  1. Empujo la primera mitad a una pila. Si encuentro una c en esa mitad → falla.
  2. Si la longitud es impar, el carácter central debe ser c.
  3. Recorro la segunda mitad y la comparo carácter a carácter con lo que sale de la pila. Si veo c en esta mitad → falla.

💻 Código

tp2_ej10.adbwith Ada.Text_IO; use Ada.Text_IO;
with Pilae;

procedure Tp2_Ej10 is

   package PChar is new Pilae (Character);
   use PChar;

   --  Pre : S contiene caracteres del alfabeto {a,b,c}.
   --  Post: True ⇔ S es de la forma W · c? · Wᴿ con W ∈ {a,b}*
   function Pertenece (S : in String) return Boolean is
      N   : constant Natural := S'Length;
      M   : constant Natural := N / 2;
      P   : Tipopila (Natural'Max (1, M));
      Y   : Character;
      Ini : Positive;
   begin
      Limpiar (P);

      --  Primera mitad → pila
      for I in S'First .. S'First + M - 1 loop
         if S (I) = 'c' then return False; end if;
         Meter (P, S (I));
      end loop;

      --  Centro (si la longitud es impar)
      if N mod 2 = 1 then
         if S (S'First + M) /= 'c' then return False; end if;
         Ini := S'First + M + 1;
      else
         Ini := S'First + M;
      end if;

      --  Segunda mitad: cada char debe coincidir con lo que sale de la pila
      for I in Ini .. S'Last loop
         if S (I) = 'c' then return False; end if;
         Sacar (P, Y);
         if S (I) /= Y then return False; end if;
      end loop;

      return True;
   end Pertenece;

   ---------- Demo ----------
   Pruebas : constant array (1 .. 7) of String (1 .. 13) :=
     ("c            ",
      "aca          ",
      "bcb          ",
      "bacab        ",
      "abbcbba      ",
      "abba         ",     --  válida: W="ab", sin C
      "abca         ");    --  inválida: la c aparece pero no es palíndromo

   Linea : String (1 .. 200);
   Last  : Natural;
begin
   --  Banco de prueba interno
   for I in Pruebas'Range loop
      declare
         T : String := Pruebas (I);
         L : Natural := T'Last;
      begin
         while L > T'First and then T (L) = ' ' loop L := L - 1; end loop;
         Put (T (T'First .. L) & " → ");
         if Pertenece (T (T'First .. L)) then
            Put_Line ("PERTENECE");
         else
            Put_Line ("no pertenece");
         end if;
      end;
   end loop;

   --  Lectura interactiva
   Put ("Ingresá una hilera: "); Get_Line (Linea, Last);
   if Pertenece (Linea (1 .. Last)) then
      Put_Line ("Pertenece al lenguaje.");
   else
      Put_Line ("NO pertenece.");
   end if;
exception
   when Underflow | Overflow =>
      Put_Line ("Error en el manejo de la pila.");
end Tp2_Ej10;
Por qué pila y no recursión: el TP pide trabajar con la estructura pila — y de hecho los palíndromos son el ejemplo canónico de uso de pila para reconocer lenguajes no regulares. Empujás la primera mitad y salís comparando con la segunda: lo que entra primero (más a la izquierda) sale último (más a la derecha) — exactamente lo que se espera para un palíndromo.
Caso borde — hilera vacía: si S'Length = 0 mi función devuelve True. Si querés que la cadena vacía no pertenezca, agregá if N = 0 then return False; end if; al inicio.

🪝 access types 🆕 new 🧹 Unchecked_Deallocation ⚠️ dangling pointers

Idea central del TP3: en Ada, type T_Ptr is access T; declara un tipo puntero. new T reserva memoria en el heap y devuelve la dirección. P.all es el valor apuntado (el operador "estrella" de C). trace paso por valor del puntero

   end Crearlista;

      Tmp : Tipolista := Lista;
   begin

         Lista := Lista.Sig;

         Tmp := Lista;

         Ptr := Ptr.Sig;
      end loop;

   end Esta;

   begin
      if Vacia (Lista) then raise Listavacia; end if;

         Lista := Nuevo;

         Ptr.Sig := Nuevo;

Ejercicio 3 — Promedio de los topes (vector de pilas dinámicas de records)

CÁ
CátedraProfe

Vector de pilas dinámicas de registros (entero + carácter). Procedimiento que devuelve el promedio de los enteros que están en el tope de cada pila. Conservar la información de la estructura.

YO
AlejoYo

📝 Idea

Para cada pila no vacía: Sacar el tope, sumarlo, e inmediatamente Meterlo de vuelta. Las pilas vacías se saltean. Al final, dividir por cuántas pilas no estaban vacías.

💻 Código

with Ada.Float_Text_IO;  use Ada.Float_Text_IO;
with Piladinamica;

procedure Tp4_Ej3 is

   subtype Indice is Positive range 1 .. 5;

   type Tipo_Reg is record
      Num : Integer;
      Car : Character;
   end record;

   package PReg is new Piladinamica (Tipo_Reg);
   use PReg;

   type Vector_De_Pilas is array (Indice) of Tipopiladinamica;

   --  Pre : ninguna.
   --  Post: las pilas quedan idénticas; result es el promedio de los Num
   --        que estaban en el tope de cada pila no vacía. Si todas estaban
   --        vacías, devuelve 0.0.
   function Promedio_Topes (V : in out Vector_De_Pilas) return Float is
      R    : Tipo_Reg;
      Suma : Integer := 0;
      Cant : Natural := 0;
   begin
      for I in Indice loop
         if not Vacia (V (I)) then
            Sacar (V (I), R);
            Meter (V (I), R);          --  ¡restauración inmediata!
            Suma := Suma + R.Num;
            Cant := Cant + 1;
         end if;
      end loop;
      if Cant = 0 then
         return 0.0;
      end if;
      return Float (Suma) / Float (Cant);
   end Promedio_Topes;

   ---------- Demo ----------

   for I in Indice loop Crearpila (V (I)); end loop;
   Meter (V (1), (Num => 10, Car => 'a'));
   Meter (V (1), (Num => 20, Car => 'b'));      --  tope V(1) → 20
   Meter (V (2), (Num => 5,  Car => 'c'));      --  tope V(2) → 5
   --  V(3) queda vacía
   Meter (V (4), (Num => 100, Car => 'd'));     --  tope V(4) → 100
   Meter (V (5), (Num => -3,  Car => 'e'));     --  tope V(5) → -3

   Put (Promedio_Topes (V), Fore => 4, Aft => 2, Exp => 0);

La pila queda con la misma secuencia de elementos pero el nodo del tope es físicamente otro — para efectos del usuario, idéntica.

Ejercicio 4 — Problema de Josephus (círculo de personas)

lista circular clásico
CÁ
CátedraProfe

Personas en círculo, cada una con un entero positivo. Se elige un nombre y un N inicial. Se cuentan N en sentido horario y se elimina la persona N. El número de la persona eliminada es el N siguiente. Imprimir el orden en que las personas son eliminadas. Ejemplo: A=4, B=6, C=2, D=1, E=9, comienzo en A con N=2 → orden: B, D, E, A. Queda C.

YO
AlejoYo

📝 Modelo

Una lista circular simplemente enlazada es la estructura natural: la última persona apunta a la primera. Llevo un puntero Ant (anterior) que me permite eliminar el siguiente en O(1). Al contar N, avanzo N−1 veces y elimino Ant.Sig; la nueva ronda empieza contando desde Ant.Sig.

🧭 Trace del ejemplo

RondaEstadoNCuenta desdeEliminaN nuevo
1A→B→C→D→E→…2AB6 (B)
2A→C→D→E→…6CD1 (D)
3A→C→E→…1EE9 (E)
4A→C→…9AA—
finqueda Corden eliminados: B, D, E, A

💻 Código

tp4_ej4_josephus.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Ada.Unchecked_Deallocation;

procedure Josephus is

   type Tnodo;
   type Tptr is access Tnodo;
   type Tnodo is record
      Nombre : Character;     --  para simplificar el ejemplo (A, B, C, ...)
      Num    : Positive;
      Sig    : Tptr;
   end record;
   procedure Free is new Ada.Unchecked_Deallocation (Tnodo, Tptr);

   --  Inserta al final manteniendo el círculo.
   procedure Agregar (Cab : in out Tptr; Nom : Character; Num : Positive) is
      Nuevo : Tptr := new Tnodo'(Nom, Num, null);
      Ptr   : Tptr;
   begin
      if Cab = null then
         Cab       := Nuevo;
         Cab.Sig   := Cab;             --  círculo de 1
      else
         Ptr := Cab;
         while Ptr.Sig /= Cab loop Ptr := Ptr.Sig; end loop;
         Ptr.Sig    := Nuevo;
         Nuevo.Sig  := Cab;
      end if;
   end Agregar;

   --  Devuelve el "anterior a Cab" (el que cierra el círculo).
   function Anterior (Cab : Tptr) return Tptr is
      Ptr : Tptr := Cab;
   begin
      while Ptr.Sig /= Cab loop Ptr := Ptr.Sig; end loop;
      return Ptr;
   end Anterior;

   --  Pre : Inicial está en la lista circular Cab.
   --  Post: imprime los nombres en el orden en que son eliminados.
   procedure Eliminar_En_Orden (Cab : in out Tptr; Inicial : Character; N0 : Positive) is
      Ant, Vict : Tptr;
      N         : Positive := N0;
      Cnt       : Positive;
   begin
      --  Posicionar Ant en el "anterior" al nodo "Inicial"
      Ant := Cab;
      while Ant.Sig.Nombre /= Inicial loop Ant := Ant.Sig; end loop;

      while Ant.Sig /= Ant loop          --  mientras quede más de uno
         Cnt := 1;                       --  Ant.Sig ya cuenta como "1"
         while Cnt < N loop
            Ant := Ant.Sig;
            Cnt := Cnt + 1;
         end loop;
         Vict := Ant.Sig;
         Put (Vict.Nombre); Put (' ');
         N        := Vict.Num;           --  N siguiente lo elige el muerto
         Ant.Sig  := Vict.Sig;
         if Vict = Cab then Cab := Ant.Sig; end if;
         Free (Vict);
      end loop;

      Put_Line ("");
      Put_Line ("Sobrevivió: " & Cab.Nombre);
   end Eliminar_En_Orden;

   ---------- Demo ----------
   Lista : Tptr := null;
begin
   Agregar (Lista, 'A', 4);
   Agregar (Lista, 'B', 6);
   Agregar (Lista, 'C', 2);
   Agregar (Lista, 'D', 1);
   Agregar (Lista, 'E', 9);

   Put_Line ("Orden de eliminación:");
   Eliminar_En_Orden (Lista, Inicial => 'A', N0 => 2);
end Josephus;

Ejercicio 6 — Lista A → Lista B (nodos repetidos consecutivamente)

listas anidadas
CÁ
CátedraProfe

Cada nodo de A es una lista de caracteres. Generar B con los nodos de A que estén repetidos consecutivamente. Ej.: A = [abcf][ber][erg][erg][mo][mo][sy][y] → B = [erg][mo].

YO
AlejoYo

📝 Idea

Comparo cada nodo de A con su siguiente. Si son iguales, copio el contenido en B y salto sobre todas las copias consecutivas. Necesito una función Iguales (Lista_Char, Lista_Char) → Boolean que compare elemento a elemento.

💻 Código

tp4_ej6.adbwith Ada.Text_IO; use Ada.Text_IO;
with Listanoordenada;

procedure Tp4_Ej6 is

   ---------- Lista de caracteres (el "valor" de cada nodo de A y B) ----------
   package LC is new Listanoordenada (Character);

   ---------- Lista cuyos nodos son LC.Tipolista ----------
   package LL is new Listanoordenada (LC.Tipolista);

   --  Pre : ninguna.
   --  Post: True ⇔ X y Y tienen los mismos caracteres en el mismo orden.
   function Iguales (X, Y : LC.Tipolista) return Boolean is
      A : LC.Tipolista := X;
      B : LC.Tipolista := Y;
   begin
      while not LC.Vacia (A) and then not LC.Vacia (B) loop
         if LC.Info (A) /= LC.Info (B) then return False; end if;
         A := LC.Sig (A);
         B := LC.Sig (B);
      end loop;
      return LC.Vacia (A) and LC.Vacia (B);
   end Iguales;

   --  Crea una copia profunda de una lista de caracteres.
   function Copiar (X : LC.Tipolista) return LC.Tipolista is
      Resultado : LC.Tipolista;
      Ptr       : LC.Tipolista := X;
   begin
      LC.Crearlista (Resultado);
      while not LC.Vacia (Ptr) loop
         LC.InsertarFin (Resultado, LC.Info (Ptr));
         Ptr := LC.Sig (Ptr);
      end loop;
      return Resultado;
   end Copiar;

   --  Pre : ninguna.
   --  Post: B contiene los nodos de A que aparecen repetidos consecutivamente,
   --        cada grupo representado una vez (con copia profunda del contenido).
   procedure Generar_B (A : in LL.Tipolista; B : out LL.Tipolista) is
      P : LL.Tipolista := A;
   begin
      LL.Crearlista (B);
      while not LL.Vacia (P) and then not LL.Vacia (LL.Sig (P)) loop
         if Iguales (LL.Info (P), LL.Info (LL.Sig (P))) then
            LL.InsertarFin (B, Copiar (LL.Info (P)));
            --  saltear todas las copias consecutivas
            declare
               Ref : LC.Tipolista := LL.Info (P);
               Q   : LL.Tipolista := LL.Sig (LL.Sig (P));
            begin
               while not LL.Vacia (Q) and then Iguales (LL.Info (Q), Ref) loop
                  Q := LL.Sig (Q);
               end loop;
               P := Q;
            end;
         else
            P := LL.Sig (P);
         end if;
      end loop;
   end Generar_B;

begin
   null;   --  el armado de A queda fuera del alcance de este snippet
end Tp4_Ej6;
Por qué Copiar y no asignar el puntero: si en B guardara LL.Info (P) directamente, B y A compartirían los nodos internos. Cualquier modificación posterior a A se reflejaría en B (aliasing). La copia profunda mantiene a B independiente.

Detalle de Ada con records mutables dentro de listas: al hacer LDir.Info (P).Empleados y luego LEmp.InsertarFin sobre eso, tiene que poder modificar el record. Si Info devuelve una copia, no funciona. La firma de Listaordenada.Info de la cátedra devuelve un valor (copia), así que para modificar de verdad hace falta o (a) modificar la firma para devolver "access" o tipo "in out", o (b) declarar campos mutables. La forma más limpia es exponer una operación Modificar en Listaordenada, o trabajar la lista de empleados como un puntero independiente y reasignarlo. Dejo el snippet conceptualmente claro; en el código real quizás ajustes alguna firma.
Acceso directo: con la lista ordenada por número, Llamada es O(n) en el peor caso (recorrido lineal con corte temprano). Si la cátedra busca O(log n), la estructura ideal es un árbol balanceado o tabla hash; con lista enlazada ordenada, el "directo" es virtual — al menos no recorrés todo siempre.

💻 Código

tp4_ej8.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Listanoordenada;
with Piladinamica;
with Coladinamica;

procedure Tp4_Ej8 is

   package LInt  is new Listanoordenada (Integer);
   package PList is new Piladinamica   (LInt.Tipolista);
   package CPila is new Coladinamica   (PList.Tipopiladinamica);

   --  Pre : la cola, la pila del frente y la lista de la cabeza no están vacías.
   --  Post: la cola y la pila vuelven idénticas; result = posición (1, 2, ...)
   --        del mayor de la lista cabeza/frente.
   function Pos_Max (Q : in out CPila.Tipocoladinamica) return Positive is
      Pila : PList.Tipopiladinamica;
      L    : LInt.Tipolista;
      Ptr  : LInt.Tipolista;
      Pos  : Positive := 1;
      Mejor: Positive := 1;
      Max  : Integer;
   begin
      --  Sacar la pila del frente (alias: la modificación que hagamos sobre
      --  Pila se ve también dentro de la cola porque copiamos un puntero).
      CPila.Supcola (Q, Pila);

      --  Sacar la lista de la cabeza
      PList.Sacar (Pila, L);

      Max := LInt.Info (L);
      Ptr := LInt.Sig  (L);
      while not LInt.Vacia (Ptr) loop
         Pos := Pos + 1;
         if LInt.Info (Ptr) > Max then
            Max := LInt.Info (Ptr); Mejor := Pos;
         end if;
         Ptr := LInt.Sig (Ptr);
      end loop;

      --  Restaurar la lista en la cabeza de la pila
      PList.Meter (Pila, L);
      --  Restaurar la pila al final de la cola (rota — ver gotcha del TP2.9)
      CPila.Inscola (Q, Pila);

      return Mejor;
   end Pos_Max;

begin
   null;
end Tp4_Ej8;

📝 Idea — preservar el orden de la cola

Para acceder al frente sin descomponer la cola, uso una cola auxiliar: pongo primero el elemento a leer (alias preservado) y luego paso los demás en orden. Al final, esa cola auxiliar reemplaza la original. Resultado: misma secuencia, todo conservado.

💻 Código

tp4_ej9.adbwith Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Listanoordenada;
with Piladinamica;
with Coladinamica;

procedure Tp4_Ej9 is

   package LInt  is new Listanoordenada (Integer);
   package CList is new Coladinamica (LInt.Tipolista);
   package PCola is new Piladinamica (CList.Tipocoladinamica);

   procedure Imprimir_Lista (L : LInt.Tipolista) is
      P : LInt.Tipolista := L;
   begin
      while not LInt.Vacia (P) loop
         Put (LInt.Info (P), Width => 4);
         P := LInt.Sig (P);
      end loop;
      New_Line;
   end Imprimir_Lista;

   --  Pre : pila no vacía, cola del tope no vacía, lista del frente no vacía.
   --  Post: imprime la lista del frente de la cola del tope; pila y cola
   --        quedan idénticas en contenido y orden.
   procedure Imprimir_Frente_Tope (P : in out PCola.Tipopiladinamica) is
      Cola_Tope    : CList.Tipocoladinamica;
      Lista_Frente : LInt.Tipolista;
      X            : LInt.Tipolista;
      Aux          : CList.Tipocoladinamica;
   begin
      PCola.Sacar (P, Cola_Tope);
      CList.Supcola (Cola_Tope, Lista_Frente);

      Imprimir_Lista (Lista_Frente);

      --  Restaurar la cola en su orden original con auxiliar
      CList.Crearcola (Aux);
      CList.Inscola (Aux, Lista_Frente);
      while not CList.Vacia (Cola_Tope) loop
         CList.Supcola (Cola_Tope, X);
         CList.Inscola (Aux, X);
      end loop;
      Cola_Tope := Aux;

      PCola.Meter (P, Cola_Tope);
   end Imprimir_Frente_Tope;

begin
   null;
end Tp4_Ej9;
Por qué la cola auxiliar funciona: insertamos primero Lista_Frente en Aux, después transferimos el resto de Cola_Tope en orden FIFO. Aux queda con la misma secuencia de elementos. Como Tipocoladinamica es un record (no un access type "naked"), la asignación Cola_Tope := Aux copia los punteros del record (frente y final), que es exactamente lo que queremos.

Ejercicio 11 — Postres con CRUD

array + listas CRUD completo
CÁ
CátedraProfe

Arreglo POSTRES ordenado alfabéticamente, donde cada elemento tiene una lista de ingredientes. Operaciones: a) imprimir ingredientes, b) insertar ingrediente, c) eliminar ingrediente, d) alta postre, e) baja postre.

YO
AlejoYo

📝 Modelo

Array de tamaño fijo + un Cant : Natural que indica cuántos postres están dados de alta. Los postres se mantienen ordenados alfabéticamente: alta inserta shifteando, baja elimina shifteando. Búsqueda binaria sobre 1..Cant para acceso O(log n).

💻 Código

tp4_ej11_postres.adbwith Ada.Text_IO; use Ada.Text_IO;
with Listanoordenada;

procedure Tp4_Ej11 is

   subtype Nombre_Postre      is String (1 .. 20);
   subtype Nombre_Ingrediente is String (1 .. 20);

   package LIng is new Listanoordenada (Nombre_Ingrediente);

   type Postre is record
      Nombre        : Nombre_Postre;
      Ingredientes  : LIng.Tipolista;
   end record;

   Max_Postres : constant := 100;
   subtype Indice is Positive range 1 .. Max_Postres;
   type Arreglo is array (Indice) of Postre;

   Postres : Arreglo;
   Cant    : Natural := 0;

   ---------- Búsqueda binaria por nombre ----------
   --  Devuelve el índice o 0 si no está.
   function Buscar (Nom : Nombre_Postre) return Natural is
      Lo, Hi, Mid : Natural;
   begin
      Lo := 1; Hi := Cant;
      while Lo <= Hi loop
         Mid := (Lo + Hi) / 2;
         if    Postres (Mid).Nombre = Nom  then return Mid;
         elsif Postres (Mid).Nombre < Nom  then Lo := Mid + 1;
         else                                    Hi := Mid - 1;
         end if;
      end loop;
      return 0;
   end Buscar;

   --  Inserta nombre en orden, devuelve la posición. Lanza Constraint_Error si lleno.
   function Posicion_Para_Insertar (Nom : Nombre_Postre) return Indice is
      I : Natural := 1;
   begin
      while I <= Cant and then Postres (I).Nombre < Nom loop
         I := I + 1;
      end loop;
      return I;
   end Posicion_Para_Insertar;

   ---------- a) imprimir ingredientes ----------
   procedure Imprimir_Ingredientes (Nom : Nombre_Postre) is
      I : Natural := Buscar (Nom);
      P : LIng.Tipolista;
   begin
      if I = 0 then Put_Line ("Postre no encontrado."); return; end if;
      Put_Line ("Ingredientes de " & Nom & ":");
      P := Postres (I).Ingredientes;
      while not LIng.Vacia (P) loop
         Put_Line ("  - " & LIng.Info (P));
         P := LIng.Sig (P);
      end loop;
   end Imprimir_Ingredientes;

   ---------- b) insertar ingrediente ----------
   procedure Insertar_Ingrediente (Nom : Nombre_Postre; Ing : Nombre_Ingrediente) is
      I : Natural := Buscar (Nom);
   begin
      if I = 0 then Put_Line ("Postre no encontrado."); return; end if;
      LIng.Insertar (Postres (I).Ingredientes, Ing);
   end Insertar_Ingrediente;

   ---------- c) eliminar ingrediente ----------
   procedure Eliminar_Ingrediente (Nom : Nombre_Postre; Ing : Nombre_Ingrediente) is
      I : Natural := Buscar (Nom);
   begin
      if I = 0 then Put_Line ("Postre no encontrado."); return; end if;
      LIng.Suprimir (Postres (I).Ingredientes, Ing);
   end Eliminar_Ingrediente;

   ---------- d) alta de postre ----------
   procedure Alta_Postre (Nom : Nombre_Postre; Ingredientes : LIng.Tipolista) is
      Pos : Indice;
   begin
      if Cant = Max_Postres then
         Put_Line ("Arreglo de postres lleno."); return;
      end if;
      if Buscar (Nom) /= 0 then
         Put_Line ("Postre ya existe."); return;
      end if;
      Pos := Posicion_Para_Insertar (Nom);
      --  Shift hacia la derecha
      for K in reverse Pos .. Cant loop
         Postres (K + 1) := Postres (K);
      end loop;
      Postres (Pos).Nombre       := Nom;
      Postres (Pos).Ingredientes := Ingredientes;
      Cant := Cant + 1;
   end Alta_Postre;

   ---------- e) baja de postre ----------
   procedure Baja_Postre (Nom : Nombre_Postre) is
      I : Natural := Buscar (Nom);
   begin
      if I = 0 then Put_Line ("Postre no encontrado."); return; end if;
      LIng.Limpiar (Postres (I).Ingredientes);
      for K in I .. Cant - 1 loop
         Postres (K) := Postres (K + 1);
      end loop;
      Cant := Cant - 1;
   end Baja_Postre;

begin
   null;
end Tp4_Ej11;
Decisión clave: la lista de ingredientes la dejé como Listaordenada — así Insertar mantiene orden alfabético sin esfuerzo. Si querés permitir duplicados (p.ej. "azúcar" en dos pasos de la receta), pasá a Listanoordenada con InsertarFin.
Cuidado con el shift en alta/baja: al hacer Postres (K+1) := Postres (K) copiás el record completo, lo que copia el puntero a la lista de ingredientes. Eso es OK porque ningún postre comparte ingredientes con otro: estás moviendo el puntero, no compartiendo lista. Si después hicieras Limpiar sobre el hueco de la fuente quedaría dangling, pero como sobreescribís hacia adelante, no hay conflicto. Es un patrón delicado: si lo dudás, escribí el shift con una variable temporal.

Ejercicio 4 — Recorrido por niveles (BFS) usando cola

iterativo cola dinámica
CÁ
CátedraProfe

Procedimiento que recorra el árbol nivel por nivel, izquierda a derecha, imprimiendo el campo DATOS. Sugerencia: usar una cola, pensar iterativamente.

YO
AlejoYo

📝 Idea (BFS clásico)

  1. Si el árbol está vacío, salir.
  2. Encolar la raíz.
  3. Mientras la cola no esté vacía: desencolar un nodo, imprimir, encolar primero el hijo izquierdo (si existe) y después el derecho (si existe).

El truco que hace que salga "izquierda a derecha en cada nivel" es justamente el orden en que encolamos: izq antes que der.

💻 Código

tp5_ej4.adbwith Coladinamica;

procedure Tp5_Ej4 is

   --  Asumiendo claves enteras
   procedure Putint (X : in Integer) is begin
      Ada.Integer_Text_IO.Put (X, Width => 4);
   end Putint;

   function "<" (A, B : Integer) return Boolean is (Standard."<" (A, B));
   function ">" (A, B : Integer) return Boolean is (Standard.">" (A, B));

   package ABB is new ArbolBinarioBusqueda_CalfuAlan
     (Integer, "<", ">", Putint);

   --  Cola que va a contener punteros a árbol (subárboles)
   package Cola_T is new Coladinamica (ABB.Tipo_Arbol);

   --  Pre : ninguna.
   --  Post: imprime los datos en orden BFS (nivel por nivel, izq → der).
   procedure Recorrer_Niveles (T : ABB.Tipo_Arbol) is
      use ABB, Cola_T;
      Q       : Tipocoladinamica;
      Actual  : Tipo_Arbol;
   begin
      if Vacio (T) then return; end if;
      Crearcola (Q);
      Inscola (Q, T);
      while not Vacia (Q) loop
         Supcola (Q, Actual);
         Putint (Info (Actual));
         if not Vacio (Izq (Actual)) then Inscola (Q, Izq (Actual)); end if;
         if not Vacio (Der (Actual)) then Inscola (Q, Der (Actual)); end if;
      end loop;
   end Recorrer_Niveles;

begin
   null;
end Tp5_Ej4;

Salida BFS: C, A, O, N, R, F, S, E, L, K

Por qué cola y no pila: con pila harías DFS (preorden / postorden); con cola hacés BFS porque los nodos se atienden en el orden en que entraron — exactamente lo que necesitamos para "primero todos los del nivel actual, después los del siguiente".

Ejercicio 5 — DespliegaPreorden con tabla de hijos

reconstrucción
CÁ
CátedraProfe

Procedimiento DespliegaPreorden que despliegue, en preorden, los elementos del árbol con su hijo izquierdo y derecho. Ej.: 50 | 15 | 62, 15 | 5 | 20...

YO
AlejoYo

📝 Idea

Hago preorden (raíz primero), pero en cada visita imprimo una fila de tabla con el valor del nodo y los valores de sus dos hijos (o un guion si no existen). Listando todas esas filas se puede reconstruir el árbol con sólo leerlas.

💻 Código

tp5_ej5.adb (cliente)with Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;

--  Versión para árboles de Integer.
procedure Despliega_Preorden (T : ABB.Tipo_Arbol) is
   use ABB;

   procedure Print_Hijo (H : Tipo_Arbol) is
   begin
      if Vacio (H) then
         Put ("    -");
      else
         Put (Info (H), Width => 5);
      end if;
   end Print_Hijo;

begin
   if Vacio (T) then return; end if;

   Put (Info (T), Width => 5);
   Put (" |");
   Print_Hijo (Izq (T));
   Put (" |");
   Print_Hijo (Der (T));
   New_Line;

   Despliega_Preorden (Izq (T));
   Despliega_Preorden (Der (T));
end Despliega_Preorden;

📤 Salida ejemplo

Para un árbol con raíz 50, hijos 15 y 62, etc.:

   50 |    15 |    62
   15 |     5 |    20
    5 |     - |     -
   20 |     - |     -
   62 |     - |     -
Por qué se puede reconstruir: al ir leyendo las filas, encontrás cada nodo por primera vez antes que sus hijos (porque es preorden). Cuando llegás a la fila de un nodo X, ya creaste a X y ahora podés crear sus hijos. Iterando, el árbol se reconstruye en una sola pasada.

Ejercicio 6 — Sumar mín + máx, e insertar

eficiente propiedad ABB
CÁ
CátedraProfe

Lo más eficiente posible: sumar el menor con el mayor del ABB y agregar ese nuevo elemento al árbol.

YO
AlejoYo

📝 Idea — aprovechar la propiedad del ABB

En un ABB, el menor es el descendiente más a la izquierda (bajás siempre por Izq hasta que no haya más); el mayor es el más a la derecha (bajás siempre por Der). Así, ambas búsquedas son O(h) (h = altura), no O(n).

💻 Código

tp5_ej6.adb (cliente, claves enteras)--  Pre : not Vacio (T)
--  Post: result = el menor elemento del árbol.
function Minimo (T : ABB.Tipo_Arbol) return Integer is
   use ABB;
   P : Tipo_Arbol := T;
begin
   if Vacio (P) then raise Arbol_Vacio; end if;
   while not Vacio (Izq (P)) loop P := Izq (P); end loop;
   return Info (P);
end Minimo;

--  Pre : not Vacio (T)
--  Post: result = el mayor elemento del árbol.
function Maximo (T : ABB.Tipo_Arbol) return Integer is
   use ABB;
   P : Tipo_Arbol := T;
begin
   if Vacio (P) then raise Arbol_Vacio; end if;
   while not Vacio (Der (P)) loop P := Der (P); end loop;
   return Info (P);
end Maximo;

--  Pre : not Vacio (T)
--  Post: T contiene el elemento (Minimo + Maximo) insertado en su posición correcta.
procedure Sumar_Extremos_E_Insertar (T : in out ABB.Tipo_Arbol) is
   use ABB;
   Suma : Integer;
begin
   if Vacio (T) then raise Arbol_Vacio; end if;
   Suma := Minimo (T) + Maximo (T);
   Insertar (T, Suma);
end Sumar_Extremos_E_Insertar;
Costo: O(h) para Minimo + O(h) para Maximo + O(h) para Insertar = O(h) total. En un ABB balanceado h ≈ log₂(n); en el peor caso h = n (árbol degenerado). No hace falta recorrer todo el árbol — esa es la diferencia con un array desordenado.
Si la suma ya está en el árbol: el package Insertar de la cátedra no rechaza duplicados (los compara con >); el comportamiento exacto depende del cuerpo. Si tu profe pidió "no insertar duplicados", envolvelo con if not Esta (T, Suma) then Insertar (T, Suma); end if;.

Ejercicio 7 — Spell checker contra diccionario en ABB

aplicación archivos
CÁ
CátedraProfe

Comparar la ortografía de un texto con palabras de un diccionario implementado como ABB. Mostrar las palabras del texto que no estén en el diccionario.

YO
AlejoYo

📝 Idea

El diccionario se carga una vez en un ABB de strings. Después, se lee el texto palabra por palabra y se consulta el ABB con Esta. Si no está, se imprime. El costo por palabra es O(log n) en promedio, mucho mejor que O(n) con lista.

💻 Código

tp5_ej7.adbwith Ada.Text_IO;     use Ada.Text_IO;
with Ada.Strings.Fixed;
with ArbolBinarioBusqueda_CalfuAlan;

procedure Spell_Checker is

   subtype Palabra is String (1 .. 30);  --  longitud máxima

   procedure Put_Palabra (P : Palabra) is begin Put (P); end Put_Palabra;
   function "<" (A, B : Palabra) return Boolean is (Standard."<" (A, B));
   function ">" (A, B : Palabra) return Boolean is (Standard.">" (A, B));

   package Dicc is new ArbolBinarioBusqueda_CalfuAlan
     (Palabra, "<", ">", Put_Palabra);

   --  Pre : Archivo abierto en modo In_File con palabras separadas por espacio/línea.
   --  Post: D queda con todas las palabras del archivo cargadas.
   procedure Cargar_Diccionario
     (Nombre_Archivo : in String; D : in out Dicc.Tipo_Arbol)
   is
      use Dicc;
      F : File_Type;
      W : Palabra;
   begin
      Crear (D);
      Open (F, In_File, Nombre_Archivo);
      while not End_Of_File (F) loop
         W := (others => ' ');
         Get (F, W);              --  leer palabra de longitud fija
         Insertar (D, W);
      end loop;
      Close (F);
   end Cargar_Diccionario;

   --  Pre : ninguna.
   --  Post: imprime cada palabra del texto que NO está en el diccionario D.
   procedure Verificar_Texto
     (Nombre_Texto : in String; D : in Dicc.Tipo_Arbol)
   is
      use Dicc;
      F : File_Type;
      W : Palabra;
   begin
      Open (F, In_File, Nombre_Texto);
      while not End_Of_File (F) loop
         W := (others => ' ');
         Get (F, W);
         if not Esta (D, W) then
            Put_Line ("Palabra desconocida: " &
                      Ada.Strings.Fixed.Trim (W, Ada.Strings.Both));
         end if;
      end loop;
      Close (F);
   end Verificar_Texto;

   D : Dicc.Tipo_Arbol;
begin
   Cargar_Diccionario ("diccionario.txt", D);
   Verificar_Texto    ("texto.txt", D);
end Spell_Checker;
Por qué ABB y no lista: con n=100.000 palabras en el diccionario y un texto de 10.000 palabras, una lista da 10.000 × 100.000 = 10⁹ comparaciones (lento). Un ABB balanceado da 10.000 × log₂(100.000) ≈ 170.000 comparaciones (instantáneo).
Caveat real del ABB simple: si insertás las palabras del diccionario ya ordenadas alfabéticamente, el ABB queda completamente desbalanceado (una lista disfrazada de árbol). Para datos reales se usa AVL o Red-Black tree. Para el TP esto no se evalúa, pero está bueno saberlo.

Ejercicio 8 — Cambio de clave con historial

CÁ
CátedraProfe

  • Historial de claves por usuario.
  • No coincidir 2+ caracteres en misma posición vs. clave anterior si la nueva es de menor o igual longitud (ej. mama → papa rechazada).
  • Si la nueva es más larga, hasta 2 coincidencias permitidas.
  • Lectura encriptada con * en pantalla.
YO

📝 Modelo

La Clave es un record con string fijo de 8 + un Largo que dice cuántos chars son válidos. El historial es una lista no ordenada (lo nuevo se inserta al principio para tener la última primero).

💻 Código

tp5_ej8.adbwith Ada.Text_IO; use Ada.Text_IO;
with Listanoordenada;

procedure Tp5_Ej8 is

   subtype Largo_Range is Natural range 0 .. 8;

   type Clave is record
      Texto : String (1 .. 8) := (others => ' ');
      Largo : Largo_Range     := 0;
   end record;

   package Hist_Pkg is new Listanoordenada (Clave);

   --  ----- Reglas de validación -----

   Clave_Invalida   : exception;
   Clave_Insegura   : exception;

   --  Pre : ninguna.
   --  Post: result = cantidad de posiciones donde A.Texto(i) = B.Texto(i),
   --        contadas hasta el min de los dos largos.
   function Coincidencias (A, B : Clave) return Natural is
      Tope : Natural := Natural'Min (A.Largo, B.Largo);
      C    : Natural := 0;
   begin
      for I in 1 .. Tope loop
         if A.Texto (I) = B.Texto (I) then C := C + 1; end if;
      end loop;
      return C;
   end Coincidencias;

   --  Pre : ninguna.
   --  Post: si la clave no cumple alguna regla, lanza Clave_Invalida o Clave_Insegura.
   --        Si pasa todas, agrega Anterior al historial.
   procedure Cambiar_Clave
     (Hist : in out Hist_Pkg.Tipolista; Anterior : in Clave; Nueva : in Clave)
   is
      Permitidas : Natural;
      Coinc      : Natural;
   begin
      if Nueva.Largo < 4 or Nueva.Largo > 8 then
         raise Clave_Invalida;
      end if;

      if Nueva.Largo > Anterior.Largo then
         Permitidas := 2;
      else
         Permitidas := 1;       --  "no permitir 2 o más" ⇔ permitir hasta 1
      end if;

      Coinc := Coincidencias (Nueva, Anterior);
      if Coinc > Permitidas then
         raise Clave_Insegura;
      end if;

      --  Aceptada: la anterior va al historial
      Hist_Pkg.InsertarPpio (Hist, Anterior);
   end Cambiar_Clave;

   --  Lectura "encriptada": muestra '*' por cada char tipeado.
   --  En GNAT/Linux real esto necesita Get_Immediate; lo dejo idiomático.
   procedure Leer_Clave (C : out Clave) is
      Ch : Character;
   begin
      C := (Texto => (others => ' '), Largo => 0);
      loop
         Get_Immediate (Ch);
         exit when Ch = ASCII.LF or Ch = ASCII.CR;
         exit when C.Largo = 8;
         C.Largo := C.Largo + 1;
         C.Texto (C.Largo) := Ch;
         Put ('*');
      end loop;
      New_Line;
   end Leer_Clave;

begin
   null;
end Tp5_Ej8;

Ejercicio 9 — Mediana del ABB (sin estructuras auxiliares)

recursión + estado propiedad inorden
CÁ
CátedraProfe

ABB con número impar de claves, sin repeticiones. Codificar una función que devuelva la mediana (la que tiene tantas claves menores como mayores). No utilizar ninguna estructura de datos auxiliar. Árbol del ejemplo (raíz 35):

              35
             /  \
           23    45
          /  \   / \
        11  28 37  52
       /  \    \    \
      9   15  31   59
YO
AlejoYo

📝 Idea

En un ABB el inorden devuelve las claves ordenadas. La mediana es la (n+1)/2-ésima clave de ese inorden. Hago dos pasadas:

  1. Cuento los nodos (sin estructura auxiliar — la pila de la recursión no cuenta como "estructura de datos auxiliar").
  2. Recorro inorden contando hasta llegar a la posición (n+1)/2; cuando llego, devuelvo esa clave.

a) Instanciación del package

function "<" (A, B : Integer) return Boolean is (Standard."<" (A, B));
function ">" (A, B : Integer) return Boolean is (Standard.">" (A, B));
procedure Putint (X : in Integer) is begin
   Ada.Integer_Text_IO.Put (X, Width => 4);
end Putint;

package ABB is new ArbolBinarioBusqueda_CalfuAlan
  (Integer, "<", ">", Putint);

b) Función Mediana

tp5_ej9.adb (cliente)--  Cuenta nodos sin estructura auxiliar (sólo recursión sobre el árbol).
function Cantidad (T : ABB.Tipo_Arbol) return Natural is
   use ABB;
begin
   if Vacio (T) then return 0;
   else return 1 + Cantidad (Izq (T)) + Cantidad (Der (T));
   end if;
end Cantidad;

--  Recorre inorden buscando el k-ésimo. K se decrementa por cada visita.
--  Cuando K llega a 0 al visitar una raíz, ese es el resultado.
procedure Buscar_K (T          : in     ABB.Tipo_Arbol;
                    K          : in out Natural;
                    Resultado  :    out Integer;
                    Encontrado : in out Boolean)
is
   use ABB;
begin
   if Vacio (T) or Encontrado then return; end if;

   Buscar_K (Izq (T), K, Resultado, Encontrado);
   if Encontrado then return; end if;

   K := K - 1;
   if K = 0 then
      Resultado  := Info (T);
      Encontrado := True;
      return;
   end if;

   Buscar_K (Der (T), K, Resultado, Encontrado);
end Buscar_K;

--  Pre : T es un ABB con cantidad IMPAR de nodos, sin claves repetidas.
--  Post: result = la clave mediana (la del medio según el inorden).
function Mediana (T : ABB.Tipo_Arbol) return Integer is
   N          : Natural := Cantidad (T);
   K          : Natural;
   R          : Integer;
   Encontrado : Boolean := False;
begin
   if N = 0 then raise ABB.Arbol_Vacio; end if;
   K := (N + 1) / 2;
   Buscar_K (T, K, R, Encontrado);
   return R;
end Mediana;

🧭 Verificación con el árbol del enunciado

Inorden del árbol: 9, 11, 15, 23, 28, 31, 35, 37, 45, 52, 59 (11 nodos, n=11, posición = (11+1)/2 = 6).

El sexto elemento del inorden es 31... espera. Recontemos: 9(1), 11(2), 15(3), 23(4), 28(5), 31(6), 35(7), 37(8), 45(9), 52(10), 59(11). La mediana queda en posición 6, valor 31.

Cuidado con la convención: "mediana = la que tiene tantas menores como mayores" implica n impar. Para n=11, hay 5 a la izquierda + 1 (mediana) + 5 a la derecha. Posición = (n+1)/2 = 6 (1-indexada). El valor 31 tiene 5 menores (9, 11, 15, 23, 28) y 5 mayores (35, 37, 45, 52, 59). Coincide. ✓
Por qué la pila de recursión "no es estructura de datos auxiliar": es una interpretación común — la cátedra suele referirse a evitar arrays, pilas, colas o listas explícitamente declaradas para almacenar datos del recorrido. Si tu profe lo interpreta más estricto, deberías hacer una solución iterativa con dos punteros Morris-traversal (O(1) extra de memoria de verdad). Eso es bastante más complejo y fuera del alcance habitual del TP — confirmá con el profe si te apura el detalle.

with Ada.Unchecked_Deallocation;

🪤 Las 4 trampas que SÍ entran al parcial

  1. Fuga (memory leak): P := new Integer; P := new Integer; — el primer bloque queda colgado.
  2. Aliasing: Q := P; hace que Q.all y P.all sean el mismo objeto. Modificar uno modifica al otro.
  3. Dangling pointer: Q := P; Free (P); — Q sigue apuntando a memoria liberada. Usarla es UB.
  4. Double free: Free (P); Free (Q); cuando P y Q apuntaban al mismo bloque.

🛡️ Receta para sobrevivir

  • Antes de asignar a un puntero que ya tenía algo: Free primero.

Trampasref
  1. Constraint_Error vs Data_Error al leer: Si la entrada no es un número → Data_Error. Si es un número pero está fuera del subtype → depende del compilador (suele ser Data_Error porque Get chequea contra el subtype antes de asignar). En código tuyo manualmente: fuera de rango → Constraint_Error.
  2. R1 := R2 vs R1.all := R2.all con punteros a records: el primero hace alias, el segundo copia los campos. Cambiar campos por uno se ve en el otro sólo en el caso del alias.
  3. Una excepción manejada DENTRO del proc no se propaga: si capturás Constraint_Error en un sub-bloque, el llamador no se entera. Y los parámetros out que no asignaste antes del raise quedan indefinidos.
  4. El subtype filtra ANTES del raise manual: Y : subtype Rango range 1..10; Get(Y); if Y=0 then raise Cero; end if; — si entra 0, el Get ya tira Constraint_Error antes de llegar al if. La excepción "Cero" queda muerta.
  5. Tipo_Indice'Image (I) trae espacio adelante: para imprimir limpio, concatená con string vacío y aplicá Ada.Strings.Fixed.Trim, o usá Put (I, Width => 0).
  6. Tipos derivados nominalmente distintos: type Km is new Integer; type Mi is new Integer; son incompatibles aunque "iguales por estructura". Tenés que convertir: Mi (Integer (X)).
  7. Los 'use' abren todo el package: si hacés use Ada.Text_IO; use Ada.Integer_Text_IO; y ambos exportan Put, las llamadas pueden ser ambiguas. Resolución: calificá (Ada.Text_IO.Put) o evitá uno de los use.
  8. El or else y el and then: son los short-circuit. and/or a secas evalúan ambos lados siempre. Para if Ptr /= null and then Ptr.Info = X hace falta and then: si usás and, evalúa Ptr.Info aún con Ptr null y tira Constraint_Error.
  9. Positive ya descarta el 0: si tu lectura usa N : Positive; Get (N);, ingresar 0 dispara Constraint_Error automáticamente. Te ahorrás un if.
  10. El declare ... begin ... end es una expresión: podés meter declaraciones locales en cualquier parte del body, no sólo arriba. Útil para tipos auxiliares dentro de un loop.

Ej 1 · Torneo de ajedrez — filtro doble en una pasada

Cantidad de jugadores variable → Listanoordenada. Las listas L1 y L2 son del mismo tipo. Una sola pasada decide cada jugador con if/elsif.

procedure Torneo_Ajedrez is

   --  INCISO A — Tipos e instanciaciones
   type TipoPieza is (Caballo, Alfil, Torre, Peon, Rey, Dama);

   type Tipojugador is record
      Numero : Integer;
      Pieza  : TipoPieza;
      Tiempo : Integer range 1 .. 10;   -- minutos

   package Lista_Jugadores is new Listanoordenada (Tipoelem => Tipojugador);

   --  INCISO B — Filtrar Rey/Tiempo y Peón/Jaque mate
   --  Objetivo: una pasada → dos listas filtradas.
   --  Entrada:  Jugadores (lista original, sólo lectura)
   --  Salida:   L1 (Rey y partida por tiempo) · L2 (Peón y jaque mate)
   --  Conserva: SÍ — recorrido con Aux, sin Insertar/Suprimir sobre Jugadores.
   procedure Filtrar
     (Jugadores : in     Lista_Jugadores.Tipolista;
      L1        :    out Lista_Jugadores.Tipolista;
      L2        :    out Lista_Jugadores.Tipolista)
   is
      Aux : Lista_Jugadores.Tipolista := Jugadores;
      J   : Tipojugador;
   begin
      Lista_Jugadores.Crearlista (L1);
      Lista_Jugadores.Crearlista (L2);

      while not Lista_Jugadores.Vacia (Aux) loop
         J := Lista_Jugadores.Info (Aux);

         elsif J.Pieza = Peon and then J.Tiempo < 10 then
            Lista_Jugadores.InsertarPpio (L2, J);
         end if;

         Aux := Lista_Jugadores.Sig (Aux);
      end loop;
   end Filtrar;

   --  INCISO C — La conservación se logra en B con Aux.

begin
   null;

Ej 2 · Mayor del tope de cada pila — vector de pilas de listas

El truco para CONSERVAR la pila sin operación Tope: Sacar el tope, usarlo, y Meterlo de nuevo. La pila queda idéntica.

mayor_de_topes.adbwith Listanoordenada;
with Piladinamica;

procedure Mayor_de_Topes is

   --  INCISO A — Tipos e instanciaciones

   --  Lista interna: enteros (cada elemento de la pila es una lista de enteros)
   package Lista_Int is new Listanoordenada (Tipoelem => Integer);

   --  Pila cuyos elementos son listas de enteros
   package Pila_de_Listas is new Piladinamica (Tipoelem => Lista_Int.Tipolista);

   --  Vector de pilas — la "estructura E" del enunciado
   subtype Indice is Integer range 1 .. 10;   -- ej.: 10 pilas
   type TipoEstructura is array (Indice) of Pila_de_Listas.Tipopiladinamica;

   --  AUXILIAR — mayor entero de una lista (sólo lectura).
   --  Evita repetir el patrón de recorrido en B.
   function Mayor_de (L : Lista_Int.Tipolista) return Integer is
      Aux    : Lista_Int.Tipolista;
      Mayor  : Integer;
      Actual : Integer;
   begin
      Mayor := Lista_Int.Info (L);     -- inicializo con el primero
      Aux   := Lista_Int.Sig (L);
      while not Lista_Int.Vacia (Aux) loop
         Actual := Lista_Int.Info (Aux);
         if Actual > Mayor then
            Mayor := Actual;
         end if;
         Aux := Lista_Int.Sig (Aux);
      end loop;
      return Mayor;
   end Mayor_de;

   --  INCISO B — Mayor del tope de cada pila → lista resultado
   --  Objetivo: recorrer el vector, tomar la lista del tope de cada pila,
   --            calcular su mayor, sumarlo a la lista resultado.
   --  Entrada:  E (vector de pilas de listas) — in out por requisito técnico,
   --            pero al finalizar queda IDÉNTICA (Sacar + Meter restaura).
   --  Salida:   Resultado (lista de enteros en orden de aparición).
   --  Conserva: SÍ, en dos niveles (pila externa y lista interna).
   procedure Mayor
     (E         : in out TipoEstructura;
      Resultado :    out Lista_Int.Tipolista)
   is
      Lista_Tope : Lista_Int.Tipolista;
      M          : Integer;
   begin
      Lista_Int.Crearlista (Resultado);

      for I in E'Range loop

            --  1) Sacar el tope (es una lista de enteros)
            Pila_de_Listas.Sacar (E (I), Lista_Tope);
            --  2) Calcular el mayor de esa lista (sin modificarla)
            M := Mayor_de (Lista_Tope);
            --  3) Sumar al resultado
            Lista_Int.InsertarFin (Resultado, M);
            --  4) Restaurar la pila volviendo a meter la lista del tope
            Pila_de_Listas.Meter (E (I), Lista_Tope);
         end if;
      end loop;
   end Mayor;

   --  INCISO C — Conservar la estructura E (dos niveles):
   --   * Lista interna: Mayor_de la recorre con Aux, no la toca.
   --   * Pila externa: Sacar + Meter del tope → la pila queda igual.

begin
   null;
end Mayor_de_Topes;

Lectura concepto a concepto:

  • "pila de colas de listas de enteros": 3 niveles anidados. P es pila → cada elemento es cola → cada elemento de cola es lista de enteros.
  • "tope de la pila": lo último que se metió en P (lo de arriba).
  • "al final de la cola": la última lista de esa cola (la que se metió última con Inscola).
  • "números negativos": los enteros < 0 de esa lista.
Las 2 trampas nuevas (importantes para el viernes):
  1. Coladinamica no tiene "ver el final". Solo Inscola (mete al final) y Supcola (saca del frente). Para encontrar la última lista, hay que vaciar la cola entera a una auxiliar y capturar el último elemento sacado.

      end if;

      --  1) SACO la cola del tope (la repongo al final).
      Pila_de_Colas.Sacar (P, ColaTope);

      --  2) VACÍO la cola entera a ColaAux para encontrar la lista
      --     del final. Lista_F se sobrescribe en cada iteración:
      --     queda con la ÚLTIMA, que era el final.
      Cola_de_Listas.Crearcola (ColaAux);
      while not Cola_de_Listas.Vacia (ColaTope) loop
         Cola_de_Listas.Supcola (ColaTope, Lista_F);
         Cola_de_Listas.Inscola (ColaAux,  Lista_F);
      end loop;

      --  Restauro ColaTope: ColaAux tiene los mismos elementos
      --  en el mismo orden original.
      ColaTope := ColaAux;

      --  3) Recorro Lista_F filtrando negativos (NO la modifico).
      AuxLista := Lista_F;
      while not Lista_Int.Vacia (AuxLista) loop
         E := Lista_Int.Info (AuxLista);
         if E < 0 then
            Lista_Int.InsertarFin (Result, E);
         end if;
         AuxLista := Lista_Int.Sig (AuxLista);
      end loop;

      --  4) Restauro la pila: ColaTope vuelve a ser el tope.
      Pila_de_Colas.Meter (P, ColaTope);
   end Negativos;


   --  INCISO C — Conservación en 3 niveles:
   --   * Pila P:    Sacar + Meter → idéntica.
   --   * Cola tope: vaciada a ColaAux y reasignada → idéntica.
   --   * Lista_F:   solo lectura con AuxLista.

   null;
end Negativos_Recu_2022;
Las 3 cosas que tenés que poder explicar en oral:
  1. ¿Por qué tres instanciaciones? Tres TADs distintos en cascada. Cada uno usa el tipo del anterior como Tipoelem. Es el patrón "tortilla de papas" — capa por capa.
  2. ¿Por qué ColaTope := ColaAux? En Ada los tipos privados de Coladinamica son records con punteros (Frente, Final). Asignar un record copia los dos punteros, así que ColaTope pasa a apuntar a los mismos nodos que tenía ColaAux. Como ColaTope estaba vacía, no hay leak.
  3. ¿Por qué in out si "conserva"? Porque Sacar exige in out. La conservación es semántica (al salir queda igual), no sintáctica. El header del procedimiento lo aclara.
